## 1. aog：规则 → Config 字段（一次性的开关）

aog 构建 `AoGCore` 时把规则翻译成 `Config` 开关（`aog/core.rs:589-640`）：

```rust
match rule.ctype.as_str() {
    "precise"         => shape_size_lower_bound = shape_size_upper_bound = area,
    "range"           => shape_size_lower_bound.max(min) / upper_bound.min(max),
    "different"       => config.all_shapes_different = true,
    "same"            => config.all_shapes_same = true,
    "mixed"           => config.adjacent_shapes_different = true,
    "differentiation" => config.adjacent_sizes_different = true,
    "block"           => config.only_rectangles = true,
    "non_block"       => config.no_rectangles = true,
    "brick"           => config.no_4_way_intersections = true,
    "ring"            => config.no_3_way_intersections = true,
    "solitary"        => config.one_symbol_per_region = true,
    _                 => {}
}
```

其它“线索型”规则在 `build` 里用 `use_*` 开关决定是否把线索编码进位域：

```rust
use_area_numbers  = 有 "area" 规则
use_compass       = 有 "compass" 规则
use_watchtower    = 有 "watchtower" 规则
use_puzzle_piece  = 有 "puzzle_piece" 规则
use_fence         = 有 "fence" 规则
use_edge_rules    = 有 heterogeneous|homogeneous|inequality|difference 任一
predefine_shapes_only = 有 "shape_pool" 规则（区域必须来自池）
```

## 2. 全局规则详解（逐个）

### 2.1 `precise` —— 精确面积

- **语义**：所有区域面积恰好等于 `area`。
- **aog**：`shape_size_lower_bound = upper_bound = area`，直接卡死搜索的尺寸范围。
- **pieces**：经 `shapes::area_bounds`（`shapes.rs:115`）设为 `(area, area)`。
- **backtrack**：`compute_area_bounds`（薄包装）经 `shapes::area_bounds` 设为 `(area, area)`。
- **validate.rs**：`validate::validate` 的 `precise` 分支（`solver/validate.rs:91-98`）逐区域比对 `area`。

### 2.2 `shape_pool` —— 形状池

- **语义**：每个区域形状必须属于池中（8 种朝向算同形，可重复使用）。
- **aog**：把所有池形状插进**形状目录** `shapes`（`aog/core.rs:798-803`），
  并置 `predefine_shapes_only`，搜索只从目录中取形状放置。
- **pieces**：直接把每个池形状的 8 种变换平铺到每个格子生成候选（`pieces.rs:224-245`）。
- **validate.rs**：`validate::validate` 的 `shape_pool` 分支（`solver/validate.rs:80-90`）——
  池形状收集统一走 `shapes::collect_pool_shapes`（`shapes.rs:75`），同时从**顶层数组**和
  **shape_pool 规则的 `params.shapes`** 收集，逐区域比对 `dihedral_key`。

### 2.3 `rose_window` —— 玫瑰窗

- **语义**：每个区域恰好包含每种符号一个。
- **aog**：原生支持。`rose_types` 收集符号类型，`rose_type_count` 记录类型数；
  符号格编码 `AREA_SYMBOL_BIT + AREA_SLASH_INDEX_BIT`；`slash_nodes` 按类型分桶。
- **rose 求解器**：整个 `solver/rose/` 都是为它写的（见 07）。
- **backtrack**：叶子处统计每种符号每区出现次数必须为 1（`backtrack.rs:545-568`）。
- **constraints.rs**（已删 2026-08-06）：原为 stub（返回 true）。
- **validate.rs**：`check_rose_window`（`solver/validate.rs:327`）——完整校验。
- **路由**：`is_rose_capable`（`mod.rs:238`）决定是否给 rose 机会。

### 2.4 `same` / `different` —— 全同 / 全异形状

- **aog**：`all_shapes_same` / `all_shapes_different`，搜索时维护
  `all_shapes_same_check_shape_index` / `all_shapes_different_check_shape_index_pool`
  做剪枝（`search.rs:239-244, 362-369`）。
- **validate.rs**：`same`/`different` 分支（`solver/validate.rs:122-133`）用 `dihedral_key` 集合判断。
- **注意**：`is_rose_capable` 要求无 `same`/`different`，因为 rose 求解器不支持。

### 2.5 `mixed` / `differentiation` —— 相邻异形 / 相邻异面积

- **aog**：`adjacent_shapes_different` / `adjacent_sizes_different`，放置时对每格调
  `check_nearby_shape` / `check_nearby_size`（`aog/core.rs:225-261`）。
- **validate.rs**：`mixed`/`differentiation` 分支（`solver/validate.rs:134-147`）经
  `adjacent_pairs_satisfy`（`solver/validate.rs:406`）遍历所有边相邻对。

### 2.6 `range` —— 面积范围

- 面积上下界已收敛：pieces / backtrack / rose 共用 `shapes::area_bounds`（`shapes.rs:115`，precise/range + 罗盘派生 min）；aog 有独立的 Config 尺寸界。
- **validate.rs**：`range` 分支（`solver/validate.rs:99-107`）。

### 2.7 `solitary` —— 独居

- **语义**：每区恰好 1 个“计线索”格（面积数字/围栏/拼块/罗盘/符号）。
- **aog**：`one_symbol_per_region`，`symbol_loc` 追踪本区符号（`search.rs`）。
- **backtrack / validate**：均有实现（validate 的 `solitary` 分支 `solver/validate.rs:148-166`）。
- **路由备注**：`mod.rs` 与 pieces 的面积上下界计算里**刻意不把 solitary 设成 1..1**
  （`pieces.rs:145-149` 注释解释了历史教训：强制 1..1 让块/独居题结构上不可解）。

### 2.8 `block` / `non_block` —— 方块 / 非方块

- **aog**：`only_rectangles` / `no_rectangles`。`block` 还会在 `build` 里**生成所有
  合法矩形**进形状目录（`aog/core.rs:904-926`）。
- **backtrack / validate**：`is_rectangle` 判断（validate 的 `block`/`non_block` 分支 `solver/validate.rs:167-180`）。
- **pieces 备注**：`block` 不约束面积（不是只有 4 格矩形），所以 pieces 的候选生成
  不加矩形限制——`validate::validate`（`block` 分支）兜底。

### 2.9 `brick` / `ring` —— 砖纹 / 环纹

- **语义**：brick 禁止顶点 4 条边界交汇（十字）；ring 禁止 3 条（T 字）。
- **aog**：`no_4_way_intersections` → `check_tatami`（`aog/core.rs:392`）；
  `no_3_way_intersections` → `check_loopy`（`aog/core.rs:409`）+ **ring T 字剪枝**
  `ring_t_junction_check`（`aog/empty.rs:274`）。
- **backtrack**：`check_vertex_ring_ok`（增量，`backtrack.rs:343`）+ `check_ring_ok`（叶子）。
- **constraints.rs**（已删 2026-08-06）：原为 stub。
- **validate.rs**：`count_boundary_edges_at_vertex` 统计每顶点边界数，
  brick=4 拒绝、ring=3 拒绝。

### 2.10 `watchtower` —— 望塔

- **语义**：顶点数字 = 接触该顶点的**不同区域数**（1..=4）。
- **aog**：编码 `VERTEX_RADAR_BIT`，`check_radar`（`aog/core.rs:438`）。
- **pieces / backtrack**：构建 watchtower 表，验证时逐个核对。
- **validate.rs**：遍历顶点统计 distinct region 数。

### 2.11 `compass` —— 罗盘

- **语义**：四个方向半平面内同区域格数（对角格算两次）。
- **aog**：`AREA_COMPASS_ENABLE` + 四个 `puzzle_compass_*` 数组，
  放置时比对方向计数（`search.rs`）。
- **pieces**：只对**强约束罗盘**（≥3 方向或条带型）生成候选（`pieces.rs:272-300`）。
- **backtrack**：叶子处 `count_directions` 核对。
- **validate.rs**：完整核对四个方向。
- **路由**：`has_constrained_compass`（`mod.rs:223`）识别强罗盘。

## 3. 边线索：四种约束的编码

边线索（双生/异生/不等号/差值）在 aog 里编码成 **LINE 位域**。映射函数
`apply_line_constraint`（`aog/core.rs:953-982`）：

| 边约束 | JSON 字段 | aog LINE 位 | 检查函数 |
|---|---|---|---|
| 异生 heterogeneous | `type:"heterogeneous"` | `LINE_DIFFERENT` | `check_edge_shape` |
| 双生 homogeneous | `type:"homogeneous"` | `LINE_EQUAL` | `check_edge_shape` |
| 不等号 inequality | `value==1` → 首端区域更大 | `LINE_LARGER`（否则 `LINE_SMALLER`） | `check_edge_shape` |
| 差值 difference | `value` | `LINE_SIZE_DIFF_BIT` 存 `value+1` | `check_edge_shape` |

> **差值为什么存 `value+1`？** 因为 0 是个合法差值（两侧面积相等），而位域 0 表示“无
> 约束”，所以用 `diff+1` 编码、读取时 `-1` 还原（`aog/core.rs:305`）。pieces /
> backtrack / validate 则直接存原始值。

### 3.1 不等号方向的约定（三处必须一致）

`apply_line_constraint` 的注释（`aog/core.rs:957-968`）写得很清楚，整条约定：

```
JSON value == 1 → 第一个端点 (r1,c1) 的区域 LARGER
JSON value != 1 → 第二个端点 (r2,c2) 的区域 LARGER
```

- C++ 的 `LINE_LARGER` = **上/左邻居更大**，即第一端点。
- Rust 两个调用点都传 `cell1_first=true`，所以化简为 `value==1 → LINE_LARGER`。
- 这条约定 Python 求解器、exact-cover、独立验证器**共享**（`validate.rs:593-600`）。

### 3.2 pieces 侧的“kind”命名

pieces 收集边约束时用了不同的内部命名（`pieces.rs:191-215`）：

```
heterogeneous → "delta"      homogeneous → "gemini"
inequality    → "inequality" difference  → "difference"
```

在 `reconstruct_and_validate` 里按 kind 校验（`pieces.rs:604-630`）。

## 5. 规则组合的两个“特殊剪枝”

1. **`shape_pool` + aog**：`predefine_shapes_only` 时 `dfs()` 的
   `SPECIAL_START_DEFAULT` 分支直接返回 -1（不再自由生长形状，`search.rs:1280`）。
2. **`rose_window` 尺寸下界**：每区至少含每种符号一个 → 尺寸下界 ≥ 类型数
   （`aog/core.rs:882-885`）。
