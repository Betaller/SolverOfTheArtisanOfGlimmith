# 08 · 验证与约束检查：错误答案是怎么被拦下的

> 阅读对象：想理解“可靠性的最后防线”的人。
> 前置：01（答案构建）、03（规则映射）。
> 代码：`solver/validate.rs`（635 行）、`shapes.rs`（共享形状/面积辅助）、
> `solver/mod.rs` 的边界尊重检查。
> （`constraints.rs` 已于 2026-08-06 删除——它的 9 条规则是恒 `true` 的 stub，
> 会让 fallback 求解器的 fence/compass/ring/rose 错误解逃过 Rust 复查，见 §1。）

---

## 1. 两套校验，各管什么

| 套 | 位置 | 谁调用 | 强度 | 作用 |
|---|---|---|---|---|
| ① 边界尊重 `regions_respect_boundaries` | `solver/mod.rs:130` | `build_solution` | 只查预画边界 | 所有非 aog 解的最后一道几何闸 |
| ② 完整独立验证器 `solver/validate.rs` | `solver/validate.rs:14` | `build_solution` / pieces / aog 出口 / rose 验收 | 完整（全 22 规则） | 所有解的统一验收闸 |

关系图：

```
aog 命中 ──► build_solution_trusted（信内部校验）
                 └─ 但 aog/mod.rs:34 出口仍跑 ② 复核一次

rose/pieces/backtrack ──► build_solution
                 ├─ ① regions_respect_boundaries（边界）
                 └─ ② validate::validate（全 22 规则复查）
pieces 内部也会跑 ②（pieces.rs:630，DLX 结果不合格 → None 继续搜）
```

> **2026-08-06 修复（删除 `constraints.rs`）**：旧版 `build_solution` 用
> `constraints::check_all` 复查，但 fence / compass / ring / rose_window /
> brick / inequality / difference / watchtower / puzzle_piece 9 条规则是恒 `true`
> 的 stub。aog 对这些组合题（如 ring+fence+rose）预算内解不出时，backtrack/pieces
> 产出的错误解会通过 stub 被标为 solved，只被 Python Router 的 IndependentValidator
> 拦下 → 判 FAIL。现在 `build_solution` / pieces 改用 `validate::validate`（与
> aog / rose 同一闸门），错误解在 Rust 内就被诚实拒绝。

> **关键不变量**：路由独立复核每个答案。`build_solution` 里任一条规则没通过，
> 返回的 `solved=false`，`solve()` 会继续尝试下一个求解器——错误答案无法“走私”。

## 2. ① 边界尊重：`regions_respect_boundaries`

`solver/mod.rs:130-172`（扁平 `Vec<Option<usize>>`，`r*w+c` 索引）：

```
对每条 is_boundary 边（水平 + 垂直）：
  两端格若都在某区域内且属于同一区域 → 违反 → false
```

为什么需要它：**pieces / backtrack 不感知预画边界**（它们只在几何上划分），
唯一保证“预画边两侧必须不同区域”的就是这道闸。

> aog 不需要这道闸——`LINE_BLOCK` 从构建起就编码了预画边，搜索时 `check_edge`
> 天然遵守。

## 3. 曾经的 ② `constraints.rs`（2026-08-06 已删除）

`constraints.rs` 曾提供 `check_rule` / `check_all` 的“轻量规则复查”，被
`build_solution` 用于非 aog 解的验收。它有两类问题：

- **9 条规则是恒 `true` 的 stub**：`fence / brick / ring / inequality / difference /
  watchtower / compass / puzzle_piece / rose_window`。原因是 `check_rule` 只拿到
  `regions`（区域列表），缺边/顶点/格子的盘面状态——而它们恰恰需要这些状态。
  这些 stub 让 fallback 求解器的错误解逃过 Rust 复查（2026-08-06 全量 verify 暴露：
  30 题「答案未通过独立验证」，全部是 fence/compass/ring/rose 相关）。
- **`check_heterogeneous` / `check_homogeneous` 是区域级全局检查**（`windows(2)`
  比全列表），而 validate.rs / Python 用的是**边级**（只查带 `==` / `!` 标记的边）——
  两套语义不一致。

修复：**删除 `constraints.rs`**，`build_solution` / pieces 改用 `solver/validate.rs`
（完整 22 规则，与 aog 出口 / rose 验收同一闸门，语义对齐 Python）。`dihedral_key` /
`is_rectangle` 等共享辅助本就在 `shapes.rs`（唯一实现），不随模块删除而丢失。

> 历史：`check_same` / `check_different` / `check_mixed` 曾用原始 `shape` Vec 比较，
> 两个互为旋转/翻转的区域会被误判为“形状不同”。已统一用 `dihedral_key()` 规范键
> （`shapes.rs:32`），`mixed` 为「相邻区域形状不同」正确语义。

## 4. ② `solver/validate.rs`：完整独立验证器

这是**最完整的校验器**，能独立检查全部 22 条规则。`validate(puzzle, regions)`：

```
validate(puzzle, regions)
│
├─ 所有可填格都被某区域覆盖；每区连通
├─ 预画边界两侧必须不同区域
├─ 每个区域算 dihedral_key（规范形状键）
└─ 逐规则校验：
     shape_pool / precise / range / area / same / different
     mixed / differentiation / solitary / block / non_block
     puzzle_piece / fence / compass / rose_window
     heterogeneous|homogeneous|inequality|difference（边约束）
     watchtower / brick / ring
```

### 4.1 几个特殊实现的细节

**边约束 `edge_constraint_ok`**（`validate.rs:573-606`）：
按区域面积 / 形状键判断 4 种边约束，与 `apply_line_constraint` 的编码约定一致
（`value==1 → 首端更大`）。

**fence 围栏**（`validate.rs:189-204, 609-656`）：
对每带 `fence_pattern` 的格，算出它所在区域在该格的 4 方向“是否为边界”位，拼成
3×3 图案，再与线索图案比较 dihedral 键。

**compass**（`validate.rs:205-248`）：四方向逐方向计数比对。

**watchtower 望塔**（`validate.rs:262-283`）：顶点 `(r,c)` 是**绝对网格角点**
（`0..=h × 0..=w`，含外边界），统计它接触的**在界、非阻塞**单元格中不同区域的个数
== watchtower。边界角点只接触 2 格（边）/ 1 格（角），同样精确匹配——官方题允许在
边界放望塔（2026-08-06 修复前模型是内部 `(h-1)×(w-1)`，转换器也丢弃边界望塔，
导致 6 道 watchtower DIFF，见 `docs/official-puzzles-status.md` 附录 A）。

**brick / ring**（`validate.rs:276-311`）：`count_boundary_edges_at_vertex` 统计
每顶点的边界数，brick 禁 4、ring 禁 3。ring 还检查**外边界几何点**（`r/c ∈ -1..h/w`），
因为 T 字可能出现在外边界上。

> 有一段注释（`validate.rs:678-691`）解释 `(None,None)` 的相邻格不算边界：
> 两块 blocked 之间共享“空区”，不是区域边界。若误计，会错误拒绝合法 ring 解。

> **brick 的 blocked 语义（2026-08-06 修复）**：旧版 brick 检查**跳过含 blocked 的顶点**
> （理由是“blocked 是空区，不是区域，不可能构成 4 路交叉”）——这是错的。1 个 blocked +
> 3 个不同区域在顶点相会时，blocked 与每个区域都不同，恰好 4 条边界 = **4 路交叉**
> （brick 禁止）。该跳过让 1301 的孪生解（单点 (7,6)，顶点 (6,5) 处 R0/R0/R1 + blocked）
> 被判合法。修复：不跳过 blocked 顶点，直接用 `count_boundary_edges_at_vertex` 的
> `(None,None)≠边界 / 其余不等=边界` 规则计数。1301 唯一解恢复为官方解 (6,7)。
> 注意：`constraints.py` 的 `check_rule_brick` 一直是对的（`count_boundary_edges_at_vertex`
> 不跳过 blocked），错的是 validate.rs 与 `IndependentValidator._check_brick`（已一并修复）。

**rose_window `check_rose_window`**（`validate.rs:327-392`）：
每种符号总数必须相等且 = m；区域数必须 = m；每区必须含所有类型各一次。

## 6. 常见误区澄清

1. **“aog 的答案不做校验”**：错。aog 内部校验权威，但 `solve_aog` 出口仍跑
   `solver/validate.rs` 复核（`aog/mod.rs:34`）。
2. **“fallback 求解器的答案被 stub 放行”**：已修复。`build_solution` / pieces 现在
   用 `solver/validate.rs` 全量复查（含 fence / compass / ring / rose_window）。
3. **“pieces 不查边界”**：对。它靠 `build_solution` 的 `regions_respect_boundaries`
   兜底，以及 `reconstruct_and_validate` 里对覆盖/边约束/望塔的自身检查。
4. **“rose 不用验收”**：错。`accept_if_valid` 强制跑 `solver/validate.rs`。
