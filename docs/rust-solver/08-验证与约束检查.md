# 08 · 验证与约束检查：错误答案是怎么被拦下的

> 阅读对象：想理解“可靠性的最后防线”的人。
> 前置：01（答案构建）、03（规则映射）。
> 代码：`constraints.rs`（336 行）、`solver/validate.rs`（635 行）、
> `shapes.rs`（共享形状/面积辅助）、`solver/mod.rs` 的边界尊重检查。

---

## 1. 三套校验，各管什么

| 套 | 位置 | 谁调用 | 强度 | 作用 |
|---|---|---|---|---|
| ① 边界尊重 `regions_respect_boundaries` | `solver/mod.rs:117` | `build_solution` | 只查预画边界 | 所有非 aog 解的最后一道几何闸 |
| ② 规则复查 `constraints::check_all` | `constraints.rs` | `build_solution` | 部分规则为 stub | 非 aog 解的规则复查 |
| ③ 完整独立验证器 `solver/validate.rs` | `solver/validate.rs` | aog 出口 / rose 验收 | 完整（全规则） | 最可信的校验器 |

关系图：

```
aog 命中 ──► build_solution_trusted（信内部校验）
                 └─ 但 aog/mod.rs:34 出口仍跑 ③ 复核一次

rose/pieces/backtrack ──► build_solution
                 ├─ ① regions_respect_boundaries（边界）
                 └─ ② constraints::check_all（规则，部分 stub）
```

> **关键不变量**：路由独立复核每个答案。`build_solution` 里任一条规则没通过，
> 返回的 `solved=false`，`solve()` 会继续尝试下一个求解器——错误答案无法“走私”。

## 2. ① 边界尊重：`regions_respect_boundaries`

`solver/mod.rs:117-159`：

```
对每条 is_boundary 边（水平 + 垂直）：
  两端格若都在某区域内且属于同一区域 → 违反 → false
```

为什么需要它：**pieces / backtrack 不感知预画边界**（它们只在几何上划分），
唯一保证“预画边两侧必须不同区域”的就是这道闸。

> aog 不需要这道闸——`LINE_BLOCK` 从构建起就编码了预画边，搜索时 `check_edge`
> 天然遵守。

## 3. ② `constraints.rs`：轻量规则复查

### 3.1 分派 `check_rule` / `check_all`

`constraints.rs:25-61`：

```rust
fn check_rule(rule, puzzle, regions) -> bool {
    match rule.ctype.as_str() {
        "area"          => check_area(puzzle, regions),
        "same"          => check_same(regions),
        "different"     => check_different(regions),
        "mixed"         => check_mixed(regions),
        "heterogeneous" => check_heterogeneous(regions),
        "homogeneous"   => check_homogeneous(regions),
        "precise"       => check_precise(regions, rule),
        "range"         => check_range(regions, rule),
        "fence"         => true,            // stub
        "solitary"      => check_solitary(puzzle, regions),
        "block"         => check_block(regions),
        "non_block"     => check_nonblock(regions),
        "differentiation" => check_differentiation(puzzle, regions),
        "brick"         => true,            // stub
        "ring"          => true,            // stub
        "inequality"    => true,            // stub
        "difference"    => true,            // stub
        "watchtower"    => true,            // stub
        "compass"       => true,            // stub
        "puzzle_piece"  => true,            // stub
        "shape_pool"    => check_shape_pool(puzzle, regions),
        "rose_window"   => true,            // stub
        _               => true,
    }
}
```

### 3.2 哪些是“真检查”

| 检查器 | 作用 |
|---|---|
| `check_area` | 数字格所在区域面积 == 数字 |
| `check_shape_pool` | 每区形状（dihedral）∈ 池（双来源收集） |
| `check_same` / `check_different` | 全同 / 全异形状（**dihedral 规范键**，与 validate.rs 一致） |
| `check_mixed` | **相邻**区域形状不同（dihedral 键，见下方注） |
| `check_heterogeneous` / `check_homogeneous` | 不全同 / 全同形状（区域级，非边级！） |
| `check_precise` / `check_range` | 面积恰好 / 面积范围 |
| `check_solitary` | 每区恰好 1 线索格 |
| `check_block` / `check_nonblock` | 每区是 / 不是实心矩形 |
| `check_differentiation` | 相邻区域面积不同 |

> **`check_same` / `check_different` / `check_mixed` 曾用原始 `shape` Vec 比较**：
> 两个互为旋转/翻转的区域会被误判为“形状不同”，导致 `different` 规则放行错误解
> （典型如 1114 的 P-五连块重复组）。现改为 `dihedral_key()` 规范键，`check_mixed`
> 也修正为「相邻区域形状不同」的正确语义（镜像 validate.rs / Python），不再是
> `!check_same` 的宽松近似。

### 3.3 哪些是 stub（`true`）

`fence / brick / ring / inequality / difference / watchtower / compass / puzzle_piece / rose_window`
在 `constraints.rs` 都是 stub。原因：这些规则需要**边/顶点/格子的盘面状态**，而
`check_rule` 只拿到 `regions`（区域列表）——缺盘面上下文。它们的真实校验在
**validate.rs**（完整版）。`build_solution` 用 `constraints.rs` 时对这些规则“放行”，
由各自求解器内部（aog / pieces 边约束 / backtrack 叶子检查）负责。

> 这解释了一个细节：pieces 解完后 `reconstruct_and_validate` 里**自己**查了边约束
> 和望塔（`pieces.rs:604-641`），`check_all` 里的 stub 不影响它。

## 4. ③ `solver/validate.rs`：完整独立验证器

这是**最完整的校验器**，能独立检查全部 22 条规则。`validate(puzzle, regions)`：

```
validate(puzzle, regions)
│
├─ 所有可填格都被某区域覆盖；每区连通
├─ 预画边界两侧必须不同区域
├─ 每个区域算 dihedral_key（规范形状键）
└─ 逐规则校验：
     shape_pool / precise / range / area / same / different
     mixed / differentiation / solitary / block / non_block
     puzzle_piece / fence / compass / rose_window
     heterogeneous|homogeneous|inequality|difference（边约束）
     watchtower / brick / ring
```

### 4.1 几个特殊实现的细节

**边约束 `edge_constraint_ok`**（`validate.rs:573-606`）：
按区域面积 / 形状键判断 4 种边约束，与 `apply_line_constraint` 的编码约定一致
（`value==1 → 首端更大`）。

**fence 围栏**（`validate.rs:189-204, 609-656`）：
对每带 `fence_pattern` 的格，算出它所在区域在该格的 4 方向“是否为边界”位，拼成
3×3 图案，再与线索图案比较 dihedral 键。

**compass**（`validate.rs:205-248`）：四方向逐方向计数比对。

**brick / ring**（`validate.rs:276-311`）：`count_boundary_edges_at_vertex` 统计
每顶点的边界数，brick 禁 4、ring 禁 3。ring 还检查**外边界几何点**（`r/c ∈ -1..h/w`），
因为 T 字可能出现在外边界上。

> 有一段注释（`validate.rs:678-691`）解释 `(None,None)` 的相邻格不算边界：
> 两块 blocked 之间共享“空区”，不是区域边界。若误计，会错误拒绝合法 ring 解。

> **brick 的 blocked 语义（2026-08-06 修复）**：旧版 brick 检查**跳过含 blocked 的顶点**
> （理由是“blocked 是空区，不是区域，不可能构成 4 路交叉”）——这是错的。1 个 blocked +
> 3 个不同区域在顶点相会时，blocked 与每个区域都不同，恰好 4 条边界 = **4 路交叉**
> （brick 禁止）。该跳过让 1301 的孪生解（单点 (7,6)，顶点 (6,5) 处 R0/R0/R1 + blocked）
> 被判合法。修复：不跳过 blocked 顶点，直接用 `count_boundary_edges_at_vertex` 的
> `(None,None)≠边界 / 其余不等=边界` 规则计数。1301 唯一解恢复为官方解 (6,7)。
> 注意：`constraints.py` 的 `check_rule_brick` 一直是对的（`count_boundary_edges_at_vertex`
> 不跳过 blocked），错的是 validate.rs 与 `IndependentValidator._check_brick`（已一并修复）。

**rose_window `check_rose_window`**（`validate.rs:327-392`）：
每种符号总数必须相等且 = m；区域数必须 = m；每区必须含所有类型各一次。

## 6. 常见误区澄清

1. **“aog 的答案不做校验”**：错。aog 内部校验权威（不跑 `constraints.rs`），但
   `solve_aog` 出口仍跑 `solver/validate.rs` 复核（`aog/mod.rs:34`）。
2. **“constraints.rs 能校验所有规则”**：错。9 条规则是 stub，真正的完整校验在
   validate.rs。
3. **“pieces 不查边界”**：对。它靠 `build_solution` 的 `regions_respect_boundaries`
   兜底，以及 `reconstruct_and_validate` 里对覆盖/边约束/望塔的自身检查。
4. **“rose 不用验收”**：错。`accept_if_valid` 强制跑 `solver/validate.rs`。
