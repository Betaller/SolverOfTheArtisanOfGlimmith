# 10 · 拼块（puzzle_piece）优化方向

> 阅读对象：关注拼块题求解性能的人。
> 前置：01（路由）、03（puzzle_piece / shape_pool 规则）、05（pieces 求解器）、06（backtrack 求解器）。

---

## 1. 规则回顾

两个关联规则：

| 规则 | 类型 | 约束 |
|---|---|---|
| `shape_pool` | 全局 | 每个区域的形状必须在形状池（`shape_pool`，允许的形状集合）中 |
| `puzzle_piece` | 局部 | 若某格有 `shape_pattern`，则该格所在区域形状必须与 pattern 匹配（dihedral key 相等） |

二者通常配合：`shape_pool` 定义可用形状集合，`puzzle_piece` 中的 `shape_pattern` 把具体形状锚定到特定格子。

**代码位置：**
- 规则校验：`rsolver/src/solver/validate.rs:80-89`（shape_pool）、`:181-191`（puzzle_piece）
- 候选生成：`rsolver/src/solver/pieces.rs:199-226`（shape_pool 放置枚举）
- AoG 原生支持：`rsolver/src/solver/aog/core.rs:753-769`（shape_pattern 标记 + 形状索引）

## 3. 当前求解路径与瓶颈

### 3.1 路径一：AoG DFS（首选，有效）

`mod.rs:55-61`：AoG 原生支持 `puzzle_piece`。在 DFS 搜索中：

```
core.rs:633-637: shape_pattern 格 → AREA_SHAPE_INDEX_BIT 标记
core.rs:754-769: 遍历所有 pattern，注册到形状库并绑定索引
search.rs: 区域生长时增量检查形状匹配（形状索引相同 + 面积相等）
```

这是**唯一有效利用拼块约束指导搜索**的路径。但 AoG 对 `rose_window` 题只用 3s 预算（`AOG_ROSE_BUDGET_MS`），之后交给 rose solver——而 rose 直接拒绝 puzzle_piece 题（见下文）。

### 3.2 路径二：Pieces DLX（167/171 题无效）

`mod.rs:97-105` → `pieces.rs`：

1. 对 shape_pool 每个形状枚举所有 dihedral 变体（`polyomino::transforms`，最多 8 个）
2. 对每个变体枚举所有合法放置（`try_place`，检查边界+blocked）
3. 建 DLX 矩阵：列=所有可填格，行=放置候选
4. 搜索精确覆盖（Dancing Links Algorithm X + MRV）
5. 事后用 `validate::validate()` 过滤违规解

**致命缺陷：DLX 要求覆盖所有可填格（精确覆盖）。** 当 `sum(piece_areas) < total_fillable` 时，任何一组放置都无法覆盖全部格子 → DLX 永远找不到解 → 穿透到 backtrack。

对于只有 4 道全铺满题能从 DLX 获益，其余 167 道**白费时间**生成候选再失败。

### 3.3 路径三：Backtrack（最后回退）

`mod.rs:108-113`：Backtrack 完全**不理解拼块约束**。它自由生长区域，只在叶子节点用 `validate::validate()` 做全量验收。`shape_pattern` 和 `shape_pool` 纯粹是事后过滤条件。

**后果：** Backtrack 在一个很大的搜索空间中盲目探索，大量叶子被 validator 拒绝。尤其对于纯拼块题（区域数 = 拼块数），backtrack 无法利用"每个区域形状已完全确定"这一强约束来剪枝。

## 4. 优化方向

### ⭐ 方向 1：Backtrack 利用 shape_pattern 预计算合法格集（影响力：最高）

**核心思路：** 把 shape_pattern 从"事后检查"升级为"搜索约束"。

对每个含 `shape_pattern` 的格，该格所在区域形状**完全已知**（到 dihedral 等价类）：

```
① 取 shape_pattern → 生成所有 dihedral 变体（≤8 个）
② 以 pattern 格为锚点反算每种变体覆盖的格子
③ 合法的锚点位置 = 变体所有格都在棋盘内 + 都不 blocked + 不跨边界
④ 回溯在该区域只从这些预计算格集中选择，跳过自由生长
```

**收益分析：**

- **纯拼块题（30 道）：** 每个区域的形状完全预知 → 回溯退化为"排列拼块"而非"生长区域"，搜索树从 O(4^N) 量级下降到 O(N!)。
- **混合规则题：** 拼块区域固定后，其余区域搜索空间大幅缩小。
- **实现成本：** 中等。需要改动 backtrack 的区域初始化逻辑，但不需要改动 DLX 或 AoG。

**相关代码：** `rsolver/src/solver/backtrack.rs` 的 `solve_backtrack` 入口和 `pick_next_cell` 区域生长逻辑。

### ⭐ 方向 2：混合求解 — 拼块预定位 + 其余格回退（影响力：高）

**核心思路：** 消除 DLX 的"全铺满"前提，改为"部分覆盖 + 移交"。

```
puzzle_piece + other_rules 题：
├─ 步骤 1：用 DLX 或穷举确定所有合法拼块放置（部分覆盖，只覆盖拼块格）
│         每个 placement = shape 的某个变体放在某个合法位置
├─ 步骤 2：对每个有效放置（满足伴生规则如 rose_window 的符号分布）
│         把拼块格从剩余格集中移除
└─ 步骤 3：其余求解器工作在剩余格集上
           backtrack → 处理一般规则 / rose → 处理 rose_window
```

**收益分析：**

- **rose_window + puzzle_piece（6 道）：** 如 0732（7×7，9 格拼块+rose），拼块定位后只剩 40 格 → rose 候选生成从 49→40 格，且拼块"打洞"破坏连通性进一步剪枝。
- **大网格小拼块：** 如 3/110（11×11，3 格 + area + solitary），拼块几乎不影响整体网格，但 piece 区域确定后至少减少回溯深度。
- **中等覆盖（50-90%，约 20 道）：** 拼块占大半，剩余少量格 → 几乎退化为纯 backtrack 小问题。

**实现成本：** 高。需要重构 pieces 求解器使其支持部分覆盖，并在 `mod.rs` 中增加"拼块解 + 移交"的调度分支。

### 方向 3：放置候选预过滤（影响力：中，成本：低）

**核心思路：** 在 `generate_all_placements` 中增加伴生规则感知的过滤，减少 DLX 行数。

```rust
// 在 pieces.rs:generate_all_placements 循环中增加：
for placement in raw_placements {
    // symbol 分布过滤（rose_window）: 一个区域不能有重复符号类型
    if has_rose && placement_has_duplicate_symbol_types(p, puzzle) { continue; }
    // solitary 过滤: 一个区域不能有 >1 个 clue 格
    if has_solitary && placement_clue_count(p, puzzle) > 1 { continue; }
    // area 过滤: 预检查面积范围
    if area_outside_bounds(p.area) { continue; }
    // fence 过滤: 放置不能跨预画边界
    if has_fence && placement_crosses_fence(p, puzzle) { continue; }
}
```

**收益：** 减少无效 DLX 行数 → 对 4 道全铺满题和部分覆盖题都能减少浪费。
**实现成本：** 低。纯过滤逻辑，不改变 DLX 或路由结构。

### 方向 4：对称性破缺（影响力：低，成本：低）

`polyomino::transforms` 为对称形状生成冗余变体。如 2×2 正方形有唯一的 dihedral key 但生成 8 个变体。可在生成阶段用 `dihedral_key` 去重：

```rust
// polyomino.rs: 在 transforms() 返回前
let mut seen_keys = HashSet::new();
result.retain(|t| seen_keys.insert(dihedral_key_from_isize(t)));
```

**收益：** placements 减少数倍 → DLX 快 + 内存降。但对搜索复杂度影响有限（DLX 仍要尝试每种布局）。

## 5. 优先级矩阵

| 方向 | 影响力 | 实现成本 | 受益题数 | 风险 | 建议顺序 |
|---|---|---|---|---|---|
| 方向 1（backtrack 预计算格集） | 极高 | 中 | 171 | 中 | **① 优先** |
| 方向 2（混合求解） | 高 | 高 | ~100 | 中 | **② 第二** |
| 方向 3（放置预过滤） | 中 | 低 | 171 | 低 | **③ 速赢** |
| 方向 4（对称破缺） | 低 | 低 | 171 | 低 | **④ 顺手** |

建议顺序：**方向 3（速赢）→ 方向 1（高影响力）→ 方向 2（长期架构）→ 方向 4（顺手）。**
