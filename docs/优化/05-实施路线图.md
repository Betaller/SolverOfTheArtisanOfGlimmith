## 2. 阶段二：rose 止血（P0-B）

### 2.1 `visited` 上限 + 克隆层消除

- **改**：`region_match.rs`：
  1. `generate_all_candidates` 的 `visited` 加硬上限（建议 50 万），超限 `break`；
  2. `candidates_by_size` 去 clone（所有权转移或存引用）；
  3. `match_regions_mrv` 的 `sized` 改按引用借用；
  4. 总候选预算（所有 seed 合计 ≤ 30 万）兜底。
- **验证**：
  - C4-2：102 MB → 期望 ≤ 50 MB 且（理想情况）在预算内解出或确定性失败；
  - 全量 rose 官方题回归：可解性不劣化（C4-2 现在也解不出，无损失）。
- **门禁**：`docs/rust-solver/07-rose求解器.md` 同步；`official-puzzles-status.md` 更新；
  全量扫描存 `results/`。

## 3. 阶段三：aog 止血（P0-A，最重回归）

### 3.1 A3 deadline 粒度加细（先做，零风险）

- 4096 步 → 512 步（`search.rs:113`）；形状循环 256 → 128（`:978`）。
- **验证**：`cargo test` + 抽查；纯时效优化不改结果。

### 3.2 A1 形状库硬上限

- **改**：`aog/core.rs` `shapes_insert` 达 `MAX_CATALOG_SHAPES`（建议先 100k）即失败；
  `aog/search.rs` `place` 在 catalog 超限时返回 -1 提前让位。
- **验证**：
  - 8×10m22 / 9x10-loopy 等病态题：峰值从 5~7 GB 降到 < 500 MB；
  - **全量官方题扫描**：DIFF / UNSOLVED 与现状对比，确认没有「原本能解、加上限后解不出」的题；
    若有，调大上限或加 A2 兜底。
- **门禁**：`docs/rust-solver/04-aog求解器.md` 同步；`official-puzzles-status.md` 更新；
  全量扫描存 `results/2026080X_<sha>_shape-catalog-cap.txt` 随提交入库。

### 3.3 A2 upper_bound 合理化（视 A1 回归结果决定）

若 A1 全量回归显示某类题因 catalog 上限丢失解，再评估对该类题收紧 upper_bound 或改路由。
