# 06 · 图论与数学规划优化方法

> **背景**：调研是否可以通过线性代数（ILP/MILP）、数学规划（CP/SAT）、图论算法优化当前求解器。
> **核心结论**：完整 MILP/CP 替换不可行（连通性约束无法紧凑编码，形状匹配是子图同构 NP 完全的），
> 但**图论方法与约束传播可作为子过程嵌入现有求解器**，解决特定规则组合的瓶颈。
> **适用场景**：Ring(环纹)、Brick(砖纹)、Mixed(混合)、Inequality(不等号)、Difference(差值)、
> Compass(罗盘)、Rose Window(玫瑰窗) 的剪枝与加速。
>
> 更新日期：2026-08-06

---

## 0. 一句话结论

**不能用线性代数/数学规划全面替代现有求解器**——核心连通性约束在 MILP 中需要指数级编码，
形状匹配（子图同构）无法线性化。但**图论提供了多项可嵌入现有搜索框架的加速方法**，
投入产出比最高的方向是：在回溯搜索中增加**约束传播**（arc consistency），
使 Inequality、Difference、Ring、Brick、Mixed 等规则从「叶节点才检查」变为「中途剪枝」。

---

## 1. 为什么完整数学规划替换不可行

### 1.1 三种范式的根本障碍

| 范式 | 连通性 | 形状匹配 | 罗盘半平面计数 | 整体评估 |
|------|--------|----------|---------------|----------|
| **MILP** | ❌ 需指数级割平面或 O(KHW) 流变量 | ❌ 子图同构不可线性化 | ❌ 需已知区域成员 | **完全不适用** |
| **CP** | ⚠️ 全局图约束 | ⚠️ TableConstraint 可行但枚举量大 | ⚠️ 需已知区域成员 | 形式上可建模，本质与当前搜索同构 |
| **SAT** | ❌ Floyd-Warshall 命题编码爆炸 | ❌ 真值表爆炸 | ❌ 同上 | 编码规模不可行 |

核心问题：这个游戏是**组合拼图问题**（泛化多连块平铺，NP 完全），不是数值优化问题。
当前 Rust 求解器采用的 DFS + DLX + 回溯策略是这个问题类的正确算法范式。

### 1.2 可线性化的子集（面积约束）

以下**面积相关规则**在区域边界已知后可归结为小规模 ILP：

| 规则 | 线性形式 | 变量数 |
|------|---------|--------|
| Precise（精确） | `a_r = N` ∀r | ≤50 |
| Range（范围） | `min ≤ a_r ≤ max` | ≤50 |
| Area Number（面积数字） | `a_r = N_i`（含线索格 i 的区域） | ≤50 |
| Inequality（不等号） | `a_u ≥ a_v + 1` | ≤50 |
| Difference（差值） | `a_u - a_v = ±D`（需符号选择） | ≤50 |
| Differentiation（差异化） | `a_u ≠ a_v`（相邻区域） | ≤50 |

这是一个 ≤50 整数变量的小规模 ILP，任何求解器都能在微秒级求解。**但不是替代，而是作为
搜索中的可行性剪枝**——给定部分区域已密封（面积确定），传播约束到相邻区域，提前排除不可能
的面积分布。

## 2. 问题的三张图

求解过程可映射到三张图上：

```
     格点图 (Primal)              边界图 (Boundary)           区域邻接图 (Region Adjacency)
  ┌───┬───┬───┐              +---●---●---●---+            ┌──────┐
  │ A │ A │ B │              |   |   |   |   |            │R0 │R1│
  ├───┼───┼───┤              ●---●═══●---●---●            │  ╳  │
  │ A │ C │ B │   ──→        |   ‖   |   |   |   ──→      │R2 │R3│
  ├───┼───┼───┤              ●---●═══●---●---●            └──────┘
  │ C │ C │ B │              |   |   ‖   |   |
  └───┴───┴───┘              +---●---●═══●---●            平面图（对偶于边界图）
                                                          Mixed 规则 = 正常着色
  单元格 = 顶点                 角点 = 顶点                   区域 = 顶点
  四邻边 = 边                  分界线 = 边界边               共享边 = 邻接边
  区域 = 连通导出子图           边界形成闭合环                四色定理适用
```

三个视角对应不同的约束，可以独立或协同进行优化。

## 3. 图论优化方案（按优先级）

### 优先级总览

| 优先级 | 方案 | 图论工具 | 目标未解题 | 难度 | 工作量 |
|--------|------|---------|-----------|------|--------|
| **P0** | 面积约束图上的差分约束传播 | Bellman-Ford / arc consistency | Ineq+Diff ~34 | 低 | 小 |
| **P0** | 边界图顶点度弧一致性传播 | 局部约束传播 | Ring+Brick ~31 | 低 | 小 |
| **P1** | 区域邻接图列表着色 | 平面图着色算法 | Mixed ~33 | 中 | 中 |
| **P1** | 边界图 GF(2) 循环正交剪枝 | 割空间/循环空间对偶 | Ring/Brick 全部 | 中 | 中 |
| **P2** | Ring+Brick 的 2-因子生成 | 一般图完美匹配 | Ring+Brick 纯题 | 高 | 大 |
| **P2** | 双符号玫瑰窗的二部图匹配 | 二分图最优匹配 | 双符号玫瑰题 | 中 | 中 |
| **P3** | 罗盘半平面约束传播 | 线性不等式传播 | Compass ~29 | 中 | 中 |

## 4. P0 · 面积约束图上的差分约束传播

### 4.1 机制

当前回溯求解器对 `difference`、`inequality` **只在叶节点**做完整检查（
`backtrack.rs:589-669` 的 `check_global_constraints`，`backtrack.rs:727-738` 的
`check_edge_rules`）。搜索树中没有任何中途剪枝，导致大量不可能满足面积约束的部分划分被展开到底。

将面积约束建模为**有向约束图** `G = (V_regions, E_constraints)`：

```
不等号边:  a_u → a_v  权 -1（即 a_u ≥ a_v + 1）
差值边:    a_u → a_v  权 -D（符号选定后；未定时两个方向都试）
精确边:    a_0 → a_u  权 N, a_u → a_0 权 -N
范围边:    a_u ∈ [min, max]
```

这是一个**差分约束系统**。固定差值符号后，Bellman-Ford 在 O(VR·ER) 内检测负环
（面积约束矛盾）并给出每个区域面积的最紧上下界 `[lb_r, ub_r]`。

### 4.2 集成方式

在回溯搜索中，每次**区域密封时**（frontier 为空，面积锁定）：

1. 将密封区域的面积固定为已知值
2. 在约束图上运行一遍 Bellman-Ford 传播
3. 若检测到负环 → 当前部分赋值不可能，**立即回溯**
4. 若某个未密封区域的 `lb_r > ub_r` → 回溯
5. 若 `lb_r` 收紧 → 更新 `area_bounds`，可能触发面积下限剪枝

回溯 `dfs` 中的调用位置：

```
check_area_lower_bounds(state)  // 现有（backtrack.rs:124）
    ↓ 新增
propagate_area_constraints(puzzle, state)  // 差分约束传播
```

### 4.3 伪代码

```rust
fn propagate_area_constraints(puzzle: &Puzzle, state: &BacktrackState) -> bool {
    let regions = state.sealed_regions();   // frontier 为空的区域
    let graph = build_difference_graph(puzzle, regions);
    // 节点 = 区域 ID，边 = 不等式/差值/精确约束
    match bellman_ford(&graph) {
        Ok(bounds) => {
            for (rid, (lb, ub)) in bounds {
                if lb > ub { return false; }
                // 更新该区域在 state 中的面积界
                if lb > state.area_lower_bound(rid) {
                    // 收紧下界，后续 check_area_lower_bounds 可利用
                }
            }
            true
        }
        Err(NegativeCycle) => false,  // 约束矛盾
    }
}
```

### 4.4 行为影响

**不改求解结果**（只增加中途剪枝，不会把合法解剪掉）。需要：
- `cargo test`（Rust 单元测试）
- 全量基准扫描验证无回归
- 重点观测 Inequality/Difference 密集的 Zone3 题（Zone3/4-difference 15 道、
  Zone3/5-inequality 19 道）

## 5. P0 · 边界图顶点度弧一致性传播

### 5.1 机制

**环纹 (Ring)**: 每个网格顶点处的边界边数 ≠ 3
**砖纹 (Brick)**: 每个网格顶点处的边界边数 ≠ 4
**Ring+Brick**: 每个内部顶点处的边界边数 ∈ {0, 2}（2-因子/环覆盖）

当前回溯在 `check_vertex_ring_ok`（`backtrack.rs:464-499`）做**局部增量检查**：
每次给格子分配区域后，检查受影响顶点的边界度。但仍是「事后检查」，没有传播推论。

### 5.2 弧一致性传播规则

对于网格顶点 v，有 4 条相关边（N/S/E/W），每条边 e 的状态 ∈ {boundary, non_boundary, unknown}：

```
规则 1（Ring）: 若已确定 3 条边为 boundary → 第 4 条必须为 non_boundary
规则 2（Brick）: 若已确定 4 条边中的 3 条（含不确定）→ 不触发（brick 只禁 4）
规则 3（Ring+Brick）: 内部顶点已确定 2 条 boundary → 其余 2 条必须为 non_boundary
规则 4（边界传导）: 若一条边 e 被强制为 non_boundary，
                 则其两侧格子必须在同一区域 → 合并两个区域的候选
规则 5（区域传导）: 若两个相邻格子在不同区域 → 它们之间的边必须是 boundary
```

这些规则构成一个**约束传播网络**，每次分配边界边后触发局部传播链，
直到达到不动点或发现矛盾。

### 5.3 集成方式

在回溯 `dfs` 的每次格子分配后（`backtrack.rs:113` 主循环 `dfs` 函数中），
在现有的 `check_watchtowers_ok` 和 `check_vertex_ring_ok` 之后，增加：

```rust
// 新增：顶点度弧一致性传播
if puzzle.has_rule("ring") || puzzle.has_rule("brick") {
    if !propagate_boundary_degrees(state, r, c) {
        // 传播发现矛盾，回溯
        undo_assignment(state, r, c);
        continue;
    }
}
```

### 5.4 行为影响

**不改求解结果**（只加速剪枝）。这是当前 `check_vertex_ring_ok` 的自然强化：
从「检查当前顶点」变为「传播到所有受影响顶点」。

## 6. P1 · 区域邻接图上的列表着色（Mixed 规则）

### 6.1 机制

**混合 (Mixed/Mingle Shape)**: 边相邻的区域必须具有不同形状。
用图论语言：**区域邻接图上的正常着色**，颜色 = 形状等价类。

区域邻接图是**平面图**（它是边界图的对偶图），四色定理保证仅满足 Mixed 只需 ≤4 种形状。
加上形状池后，每个区域的可用形状受限于面积匹配的池中形状——这是**列表着色**问题。

### 6.2 快速必要性检查（O(1) 剪枝）

```
若 |{池中面积合法的形状}| < 区域邻接图的色数 → Mixed 不可能满足
```

对任意平面图，色数 ≤ 4。但如果存在完全子图 K_k（k 个区域两两相邻），
则色数 ≥ k。对网格划分最多 4 个区域可在一点交汇（望塔=4），
因此不含望塔时最大团 ≤ 4、有色数 ≤ 4。

### 6.3 可行性检查（DLX 找到划分后）

在 `reconstruct_and_validate`（`pieces.rs:280`）中，验证通过后再加一步
Mixed 可行性检查，代替当前 `check_mixed` 的 O(区域×边) 遍历：

```rust
fn check_mixed_coloring(regions: &[RegionInfo], puzzle: &Puzzle) -> bool {
    // 1. 构建区域邻接图
    let adj = build_region_adjacency(regions, puzzle);
    // 2. 对每个区域计算可用形状列表（按面积筛选形状池）
    let available_shapes = compute_available_shapes(regions, puzzle);
    // 3. 列表着色（回溯+传播，≤50 顶点，微秒级）
    list_coloring(&adj, &available_shapes).is_some()
}
```

### 6.4 增量剪枝（回溯搜索中）

在回溯搜索中维护区域形状的可能集合：

```
初始：每个区域的形状候选 = 所有面积匹配的池中形状
每次合并两个区域：候选取交集
若某个区域的候选为空 → 剪枝
若两个相邻区域都被迫选同一形状 → 剪枝
```

### 6.5 行为影响

**不改求解结果**（只加速 Mixed 验证）。注意：若形状池为空，
则 Mixed 对自由形状的约束更弱——所有区域的形状候选都是「所有可能的多连块」，
实际颜色数极大，列表着色检查无意义。仅在**形状池非空**时启用此优化。

## 7. P1 · 边界图 GF(2) 循环正交剪枝

### 7.1 理论

在网格**格点邻接图** G 上，取一个边集 B（boundary edges）。
B 分隔不同区域 ⇔ B 是 G 的一个**割边集**（cut-set）⇔ B 属于 G 的**割空间**（cut space）。

在 GF(2) 上，**割空间是循环空间的正交补**：

```
C(G) = Z(G)^⊥

即：B 是割边集 ⇔ 对 G 的每个循环 C，|B ∩ C| ≡ 0 (mod 2)
```

### 7.2 线性方程组

固定 G 的一棵生成树 T，每条非树边 e∉T 定义唯一的基本循环 C_e。
边界边集 B 合法的必要条件是：

```
∀e ∉ T:  Σ_{e' ∈ C_e} x_{e'} ≡ 0 (mod 2)
         其中 x_{e'} = 1  ⇔ e' 是边界边
```

网格图约有 **H×W** 个基本循环。这是一个 GF(2) 线性方程组，
可在 O((HW)³) 用高斯消元求解，或在线维护（每次赋值一个 x_e 后检查是否有矛盾）。

### 7.3 可集成性

这部分在实际中可能**不必要**。原因：
- 边界度顶点约束（Ring/Brick/Watchtower）+ 区域连通约束已经隐含了循环正交条件
- GF(2) 方程只是必要条件，不保障区域连通性
- O((HW)³) 对于 16×16 网格是 O(256³) ≈ 1.7×10⁷，开销显著

**建议**：如果 P0 顶点度传播效果不够，再将此作为增强方案。

### 7.4 更轻量的替代

不做完整 GF(2) 消元，只在每次边界边赋值后检查**4-循环**（格子的 2×2 方块）：

```
对每个 2×2 方块：
  若三边已是边界，第四边必须也是边界（mod 2 = 0）
  若两边已是边界（对边），另两边必须同为边界或同非边界
```

这是 GF(2) 条件的局部特例，O(1) 检查，覆盖了实际中最常见的矛盾。

## 8. P2 · Ring+Brick 的 2-因子生成

### 8.1 理论

当同时存在 Ring+Brick 时，内部顶点的边界度只能为 0 或 2。
因此**边界图是网格顶点图的一个 2-因子**（若干顶点不交的环的并集）。

**2-因子问题可在多项式时间求解**：
1. 构造辅助图 H：将每个顶点 v 替换为 gadget（7-顶点子图）
2. H 上的完美匹配 ↔ 原图的 2-因子
3. 用 Edmonds 开花算法（O(V³)）

对于最大 17×17 = 289 个顶点的网格，这非常快。

### 8.2 生成-验证模式

对于**纯 Ring+Brick+Watchtower（无形状/面积/符号约束）**的谜题：

```
1. 生成所有 2-因子（环覆盖）候选
2. 按望塔约束过滤
3. 检查每个环覆盖对应的区域划分是否满足其余规则
```

### 8.3 现状评估

Ring+Brick 是 Zone3/2-loopy 的 31 道未解题的核心约束，
但这些题**不纯**——大多同时有 area/fence/rose_window 等规则。
纯 Ring+Brick 题很少。因此这个方向**优先级较低**，
受影响的题可以用 P0 边界度传播 + 现有回溯解决。

## 9. P2 · 双符号玫瑰窗的二部图匹配

### 9.1 理论

玫瑰窗 (Rose Window) 最简形式：K=2 种符号类型（A 和 B），每种 M 个。
需要配对为 M 对 (A,B)，每对进入同一区域，恰好覆盖所有格子。

符号配对问题 = **带权二部图完美匹配**：
- 左部 = M 个 A 符号所在格子
- 右部 = M 个 B 符号所在格子
- 边权 = 两个格子的曼哈顿距离或连通区域的面积下界

在 O(M³) 内求解最优完美匹配（如匈牙利算法）。

### 9.2 快速配对 + 区域生长

```
1. 对每个 A 和 B，计算它们能共同生长的区域大小下界（最短路径内非 blocked 格数）
2. 若 region_size ≤ min_area 则不可配对（删除该边）
3. 在剩余二部图上求完美匹配
4. 若不存在完美匹配 → 无解
5. 对匹配的 M 对 (A,B)，每对生长为一个区域（边界由其他约束决定）
```

### 9.3 集成位置

在 `rose::solve_rose`（`rose/mod.rs`）入口处，检测 K=2 时优先使用匹配路径：

```rust
if symbol_types.len() == 2 {
    if let Some(solution) = bipartite_rose(puzzle, timeout_ms) {
        return Some(solution);
    }
}
// fallback to existing region_match + rose_growth
```

### 9.4 行为影响

可能改变可解性（新路径可能解出之前 rose 解不出的 K=2 题）。
需官方题库 rose 题全量回归。

## 10. P3 · 罗盘半平面约束传播

### 10.1 罗盘约束的线性形式

罗盘格 (r,c) 的值 (N,S,W,E) 定义了其区域在四个半平面的格数：

```
Σ_{i<r, 所有j} x_{(i,j)∈R} = N  （北）
Σ_{i>r, 所有j} x_{(i,j)∈R} = S  （南）
Σ_{所有i, j<c} x_{(i,j)∈R} = W  （西）
Σ_{所有i, j>c} x_{(i,j)∈R} = E  （东）
```

其中 `x_{cell∈R}` 表示该格是否属于罗盘格所在的区域。

虽然完整的区域成员分配是组合问题，但**边界框推导**是纯算术的：

```
区域的最小行范围： [r - N, r + S]
区域的最小列范围： [c - W, c + E]
区域的最小面积：   1 + N + S + W + E - |对角线交集|
```

### 10.2 约束传播

若两个罗盘格的边界框不重叠 → 它们不能在同一个区域
若罗盘格 A 的东=3 且西=2，且其区域面积上界=6 → 南+北 ≤ 0 → 区域只有一行

这些传播可以大幅缩小候选区域的空间。

### 10.3 现状

Compass 是 Zone3/6-compass-main 29 道未解题的核心瓶颈。但罗盘传播
需要更复杂的实现（需要考虑连通性），排在 P0/P1 之后。

## 11. 不推荐的数学规划方案

以下方向经过分析**不建议投入**：

| 方向 | 不推荐原因 |
|------|-----------|
| 完整 MILP 建模 | 连通性需指数级编码，16×16 网格不可行 |
| OR-Tools CP-SAT 整体求解 | 与现有搜索同构，通用传播器不如领域剪枝 |
| 完整 SAT 编码 | 连通性编码量爆炸 |
| 谱图论 (Spectral) | 拉普拉斯特征值对区域验证开销大于 BFS |
| 树宽 DP (Treewidth) | 贝尔数 B_16 ≈ 10¹⁰，状态空间不可行 |

唯一值得后续调研的数学规划方向：对于**纯 Block (Boxy) 规则**的谜题（所有区域为矩形），
矩形划分是经典 CP 问题，CP-SAT 的矩形打包可能快于通用回溯。但当前 Block 题已通过
形状池合成+DLX 解决（见 `docs/official-puzzles-status.md` 2026-08-05 记录），收益不多。

- 基准结果存入 `results/` 随提交入库
