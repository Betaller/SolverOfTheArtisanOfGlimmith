# 07 · 数学规划建模分析

> **背景**：系统评估 ILP（整数线性规划）、CP（约束规划）、SAT/SMT、混合整数非线性规划
> （MINLP）对《格里米斯的工匠》的建模能力。不预设结论，逐规则分析编码可行性与规模。
> **结论**：整体 MILP/CP 替换不可行，但部分子问题可精确建模，**可作为搜索中的剪枝子过程**。
>
> 更新日期：2026-08-06

---

## 0. 核心结论

| 范式 | 完全建模 | 部分子问题 | 推荐用途 |
|------|---------|-----------|---------|
| **ILP/MILP** | ❌ | ✅ 面积约束、边界度 | 面积可行性检测 |
| **CP** | ⚠️ 理论可行 | ✅ 全部子问题 | 候选区域生成 |
| **SAT** | ❌ | ✅ 边界图（Ring/Brick） | 边界图快速否决 |
| **SMT** | ❌ | ✅ 面积+布尔组合 | 差分约束矛盾检测 |
| **0-1 二次规划** | ❌ | ⚠️ 罗盘 | 不推荐 |
| **网络流** | ❌ | ✅ 分割可行性 | 连通性必要条件 |

## 1. 变量体系的四种选择

建模的第一步是选择决策变量。每种选择决定了后续约束的表达能力。

### 1.1 方案 A：格-区域分配变量

```
x_{i,j,k} ∈ {0,1}  — 格子 (i,j) 是否属于区域 k
K = 区域数量，需预知或取上界（≤ fillable_cells）
变量总数：H × W × K ≤ 256 × 256 = 65536
```

**优点**：区域成员关系直接可读，面积 = Σ_{i,j} x_{i,j,k}
**缺点**：
- 连通性约束需要指数级割平面或 O(KHW) 流变量
- 区域 k 的标签置换对称性（区域编号可任意置换导致巨大对称群）
- K 未知时需要枚举

### 1.2 方案 B：边界边变量

```
b_e ∈ {0,1}  — 内部边 e 是否为分界线
变量总数：H×(W-1) + (H-1)×W ≤ 480（16×16）
```

**优点**：变量数最少，Brick/Ring 约束是局部的，围栏可固定变量
**缺点**：
- 从边界边推断区域成员需要 BFS/连通分量计算（非线性）
- 区域的形状、面积、符号等约束无法直接表达
- 需要额外约束保证边界边形成合理的划分

### 1.3 方案 C：格-区域代表变量（单源指派）

```
y_{i,j} ∈ {0,...,K-1, new}  — 格子 (i,j) 的区域 ID
额外约束：同一区域 ID 的格子连通
```

就是当前 Rust 求解器的 `cell_to_region: Vec<Option<usize>>`（`backtrack.rs:58`）。
CP 最自然的建模方式，但 ILP 需要处理连通性。

### 1.4 方案 D：形状放置变量（DLX 建模）

```
z_{p,o,r,c} ∈ {0,1}  — 形状 p（8 朝向之一）是否锚定在 (r,c)
约束：每个格子恰好被一个形状覆盖
```

当前 pieces 求解器的建模（`pieces.rs`）。对于形状池谜题非常自然，
但对于无形状池的自由形式题，需要枚举所有可能的多连块形状。

## 2. 逐规则 MILP 编码分析

### 2.1 可直接线性化的规则

#### 精确 (Precision) — 方案 A

```
Σ_{i,j} x_{i,j,k} = N    ∀k
```
线性等式，O(K) 个约束。

#### 范围 (Range) — 方案 A

```
min ≤ Σ_{i,j} x_{i,j,k} ≤ max    ∀k
```
线性不等式，O(K) 个约束。

#### 面积数字 (Area Number) — 方案 A

```
Σ_{i,j} x_{i,j, region_of(r,c)} = number    ∀有数字的格子 (r,c)
```
格-区域分配确定后是线性约束。但 `region_of(r,c)` 是决策变量 → 需要 big-M：
```
-M·(1 - x_{r,c,k}) ≤ Σ_{i,j} x_{i,j,k} - number ≤ M·(1 - x_{r,c,k})
```

#### 不等号 (Inequality) — 方案 A

对于边 e 分隔区域 u 和 v，若 u 更大：
```
Σ_{i,j} x_{i,j,u} ≥ Σ_{i,j} x_{i,j,v} + 1
```
但两边是不同区域的前提需要 b_e = 1：
```
b_e = 1 ∧ side_u(e) = u ∧ side_v(e) = v  →  a_u ≥ a_v + 1
```
指标积 → 需要 big-M 松弛。

#### 差值 (Difference) — 方案 A

```
b_e = 1  →  |Σ x_{i,j,u} - Σ x_{i,j,v}| = D
```
含绝对值，可用辅助变量 `d⁺, d⁻` 线性化：
```
Σ x_u - Σ x_v = d⁺ - d⁻
d⁺ + d⁻ = D
d⁺, d⁻ ≥ 0
```
再加 big-M 关联 b_e。

#### 差异化 (Differentiation) — 方案 A

```
a_u ≠ a_v   对所有相邻区域对 (u,v)
```
用 big-M 和辅助二元变量 `δ_{u,v}`：
```
a_u - a_v ≥ 1 - M·(1-δ_{u,v})
a_v - a_u ≥ 1 - M·δ_{u,v}
```
O(邻接边数) 个约束。

### 2.2 需要指数级编码的规则

#### 所有形状相关规则 (Shape Pool, Polyomino, Gemini, Delta, Mixed, Same, Different)

根本困难：**子图同构等价类无法用 MILP 约束表达**。

给定一个区域（一组格子），判断其形状是否匹配池中某个形状的 8 种朝向之一，
等价于判断该区域的格子集在 D4 变换下是否与某个池形状一致。

这是**二次赋值问题 (QAP)** 的特殊情况，而 QAP 是 NP 完全的。更根本的是：
形状等价是格子的**相对位置关系**，不是它们的坐标数值。MILP 无法表达这种纯组合关系。

具体来说，对于形状池规则，需要：
```
∀区域 k, ∃形状 s ∈ pool, ∃变换 t ∈ D4:
    { (i,j) : x_{i,j,k} = 1 } ≡ t(s)
```
其中 ≡ 是集合等价。这需要枚举「形状 s 的变换 t 锚定在 (r,c)」的所有可能性→
方案 D 的指数级变量。

### 2.3 需要辅助流变量的规则

#### 连通性

每个区域必须是 4-连通子图。对区域 k 固定一个"源"格 s_k，要求从 s_k 出发
到区域中所有格存在流：

```
流变量 f_{i,j}^{dir} ≥ 0   每条边两个方向
对于区域 k:
  源 s_k 净出流 = Σ_{(i,j)≠s_k} x_{i,j,k}
  每个非源格 (i,j) 净入流 = x_{i,j,k}
  流只能在 x_{i,j,k}=1 的格子上通过
```

需要 O(K × H × W) 个连续变量和 O(K × H × W) 个约束。
对于 16×16 网格和 50 个区域，约 12800 变量 + 约束，规模尚可。
但流量守恒 + 二元变量 x 的积约束需要进一步 big-M 松弛。

加上形状约束需要的形状放置变量后，模型规模爆炸。

## 3. 约束规划 (CP) 建模

CP 是最接近「完全建模」的范式，因为它原生支持：
- 有限域变量（格→区域映射）
- 全局约束（连通性、基数、表格）
- 搜索+传播机制

### 3.1 CP 中的自然建模

```minizinc
% 变量
array[1..H, 1..W] of var 1..K: region;   % 每格属于哪个区域
array[1..K] of var 1..H*W: area;           % 每区域面积

% 连通性 (使用连通全局约束或自定义传播器)
constraint connected(region, k) forall k in 1..K;

% 面积
constraint area[k] = sum(i,j) (region[i,j] == k) forall k;

% 形状池
constraint forall(k) (
    exists(s in pool) (shape_of(region, k) == s)
);

% 玫瑰窗
constraint forall(k) (
    count_eq(region, k, symbol_type_A) == 1 /\
    count_eq(region, k, symbol_type_B) == 1
);

% 边界度（Ring/Brick）
constraint forall(vertex v) (
    degree(v, region) != 3  % Ring
);
```

### 3.2 CP 的核心困难

虽然有表达力，但 CP 求解器的**通用传播器不如领域特定剪枝有效**：

| 约束 | CP 传播器 | 当前 Rust 剪枝 | 效果对比 |
|------|----------|---------------|---------|
| 连通性 | 图约束（弱传播） | BFS flood-fill（精确） | Rust 更强 |
| 形状匹配 | TableConstraint（枚举） | 规范键 + 哈希集（O(1)） | Rust 更快 |
| 边界度 | 度数和约束（弱） | 局部增量检查 + 传播计划 | CP 可能更好 |
| 面积和 | 求和约束（强） | check_area_lower_bounds | 相当 |
| 罗盘 | 困难（需要全局视图） | DFS 枚举候选 | Rust 更强 |

### 3.3 CP 加速特定子问题的场景

CP 在以下场景可能有优势：

**面积组合枚举**：当前 `rose::region_match::enum_area_combos_bounded` 是自写的
MRV 回溯。CP 的求和约束传播可以更快地找到可行的面积分配。

**Rectangle packing (Boxy)**：CP 有专门的矩形打包约束 (`geost`, `diffn`),
对于 Block 规则可以极快地找到矩形划分。但当前已通过形状池合成+DLX 覆盖了大多数 Block 题。

**望塔 (Watchtower) + 边界度联合**：CP 的 `count` 约束天然适合「恰好 N 个不同区域
接触某顶点」的语义。

## 4. SAT/SMT 建模

### 4.1 SAT 建模边界图

边界图的布尔变量数 = 内部边数 ≤ 480，SAT 求解器对此规模非常快。

对每个顶点 v（4 条相关边 e1..e4），Ring（≠3）的 SAT 编码：

```
禁止恰好 3 条边为真（用排序/加法器网络）：
  对 {e1,e2,e3,e4} 中任意 3 条边，禁止 "这 3 条为真且第 4 条为假"
  共 4 个 clause
```

Brick（≠4）：
```
禁止全部 4 条边为真：
  ¬(e1 ∧ e2 ∧ e3 ∧ e4)
  1 个 clause
```

对整个网格 ≤ (H+1)×(W+1) ≤ 289 个顶点，SAT 编码约 2000 个 clause，
任何现代 SAT 求解器在**微秒级**返回可满足性或反例。

### 4.2 SAT 作为快速否决器

集成方式：

```rust
fn is_boundary_feasible(partial_edges: &[Option<bool>]) -> bool {
    let mut sat = SatSolver::new();
    // 添加 Ring/Brick clause
    for each vertex { add_degree_clauses(&mut sat); }
    // 固定已知边
    for (e, val) in partial_edges {
        if let Some(v) = val { sat.assume(e, v); }
    }
    sat.solve().is_sat()  // 微秒级
}
```

在回溯搜索中，每当边界边状态变化时调用。若 UNSAT，则当前分支不可能，立即回溯。

**优点**：极快（微秒级），只依赖边界拓扑（与区域形状/面积无关）
**限制**：只检查边界图拓扑可行性，不保障区域连通性

### 4.3 SMT 的增量价值

SMT = SAT + 理论求解器（如线性算术 LIA）。可以混合：

```
SAT 部分：边界边变量 b_e ∈ {0,1}（Ring/Brick/Watchtower）
LIA 部分：区域面积 a_k ∈ ℤ（Inequality/Difference/Precise）
桥接：Σ 区域 k 的格子 = a_k
```

对于**区域未定、但面积约束密集**的题，SMT 可同时传播边界布尔约束和面积算术约束。
但实际中往往要么边界图稀疏（面积约束无意义），要么边界图密集（面积已由其他线索确定）。

## 5. 网络流建模

### 5.1 问题：给定一组必需格（线索格），是否存在包含它们的大小为 N 的连通区域？

这是**连通 k-子图问题（Steiner 树变种）**：

```
给定：网格图 G(G=(V,E))，必需格 S ⊆ V，目标大小 N
问题：是否存在连通子图 T = (V_T, E_T) 使得 |V_T| = N 且 S ⊆ V_T？
```

**在一般图上 NP 完全**。在网格上，对于小 N（≤ 12，pieces 求解器的 MAX_AREA_TARGET），
枚举所有多连块是可行的。对于大 N（> 12），当前只能回溯搜索。

### 5.2 流公式的必要条件

对连通子图问题的**多商品流**松驰：

```
设必需格 S = {s_1, ..., s_m}
对每个 s_i 到每个候选格 v，定义流 f^i_v（从 s_i 发出的商品流）

约束：
  每个商品 i 从 s_i 流出 1 单位
  每个候选格 v 最多接收 m 单位总流
  流只能在"选中"边上通过
```

这是一个**松驰**（必要条件不是充分条件）：原始连通子图解存在 → 流松驰可解，
但流松驰可解 ⇏ 连通子图存在。

### 5.3 实用价值

流松驰可在**微秒级**提供必要条件，用于快速剪枝：
若流松驰不可行 → 原始问题不可行（剪枝）；若可行 → 不保证解存在（继续搜索）。

当前 Rust 求解器中的 `empty_area_check` flood-fill（`aog/empty.rs:332-472`）
和 rose solver 中的 `can_partition`（`rose/region_match.rs`）
已经提供了类似功能，且更精确（因为它们是连通性精确检查而非松驰）。

## 6. 子问题最佳建模方式对照表

| 子问题 | 推荐范式 | 变量/约束规模 | 求解耗时 | 集成点 |
|--------|---------|-------------|---------|--------|
| 面积可行性检测 | **ILP** (单纯形/分支定界) | ≤50 变量，≤200 约束 | <1ms | backtrack `check_area_lower_bounds` |
| 边界图 Ring/Brick 可行性 | **SAT** (CDCL) | ~480 变量，~2000 clause | <1ms | backtrack `check_vertex_ring_ok` |
| 面积组合枚举 | **CP** (求和约束传播) | ≤30 变量 | <10ms | rose `enum_area_combos_bounded` |
| 矩形划分 (Boxy) | **CP** (diffn/geost) | ~200 变量 | <1s | pieces 合成形状池前 |
| Mixed 形状分配 | **ILP** (图着色编码) | ≤50×20 变量 | ~1ms | DLX 解验证后 |
| 双符号玫瑰配对 | **二分匹配** (匈牙利) | M² 边，M≤55 | <10ms | rose 入口 |
| 自由多连块枚举 | **枚举+剪枝**（非数学规划） | — | ms~s | pieces `generate_polyominoes` |

## 7. 为什么混合整数非线性规划 (MINLP) 不适合

MINLP 理论上可以处理**二次约束**，如：

```
连通性：x_{i,j,k} · x_{i',j',k} 指示两格同区域
罗盘：Σ_{i<r} x_{i,r} · x_{i,compass_region} = N
```

但在实践中：
- **非凸性**：二元变量 + 乘积 = 非凸可行域，全局最优算法（空间分支定界）极慢
- **没有 MINLP 求解器能处理 65k 变量**（方案 A 的变量数）
- 即使对于 6×6 = 36 格，MINLP 求解器（如 BARON、SCIP）也无法在合理时间求解

## 8. 混合架构：数学规划作为搜索加速器

推荐架构不是替换现有求解器，而是在搜索的**关键节点**调用数学规划子过程：

```
              ┌────────────────────────────┐
              │    Solver Router (mod.rs)   │
              └──────────┬─────────────────┘
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
    ┌─────────┐    ┌──────────┐    ┌──────────┐
    │AoG DFS  │    │  Pieces  │    │Backtrack │
    │         │    │  (DLX)   │    │  DFS     │
    └────┬────┘    └────┬─────┘    └────┬─────┘
         │              │               │
         │     ┌────────┴────────┐      │
         │     │  验证混合着色    │      │
         │     │  (ILP图着色)    │◄─────┤
         │     └─────────────────┘      │
         │                              │
         ▼         ┌────────────────────┤
    ┌──────────┐   │  面积ILP可行性     │
    │ GF(2)    │   │  (Bellman-Ford)    │
    │ 循环检查 │   └────────────────────┘
    └──────────┘            │
                   ┌────────┴────────┐
                   │  SAT边界图否决   │
                   │  (Ring/Brick)    │
                   └─────────────────┘
```

关键原则：
1. **数学规划子过程只负责"否决"（证明不可行），不负责"构造"（找解）**
2. **构造解的工作仍由 DFS/DLX/回溯完成**
3. **数学规划子过程在搜索树节点被调用，输入是当前部分赋值，输出是可行/不可行**

## 9. 与图论方法的互补关系

图论方法（`06-图论与数学规划优化方法.md`）关注：
- 图结构的组合性质（着色、匹配、因子）
- 约束传播（arc consistency）
- 多项式时间精确算法

数学规划方法（本文）关注：
- 线性不等式系统（面积约束）
- 可满足性（边界图的 SAT 编码）
- 全局优化（CP 全局约束）

两者互补：图论方法做**结构推理**（拓扑可行性），数学规划做**数值推理**（面积/计数可行性）。

## 10. 实施建议

| 阶段 | 内容 | 依赖 | 预期收益 |
|------|------|------|---------|
| Phase 1 | Bellman-Ford 面积传播 + SAT 边界图否决 | 轻量（可嵌入，无外部依赖） | Inequality/Diff/Ring/Brick 题加速 |
| Phase 2 | ILP 图着色验证（Mixed） | 轻量（小 ILP，可手写分支定界） | Mixed 题加速 |
| Phase 3 | CP 面积组合枚举（替代 rose 自写） | 需引入 CP 库或手写传播 | 玫瑰窗大网格题 |
| Phase 4 | 完整 CP 矩形划分（Boxy 专用） | 需 CP 库 | 可能不必要（已覆盖） |

所有阶段的首选实现方式：**在 Rust 中手写轻量算法**（Bellman-Ford、小型分支定界、
简单的 SAT DPLL），而非引入外部求解器依赖（OR-Tools、MiniSat 等）。
原因是子问题规模极小（≤50 变量），手写实现的常数因子远优于通用求解器的调用开销。
