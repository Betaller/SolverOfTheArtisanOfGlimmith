# 10 · 专用求解器方案：针对特定规则组合的定向求解

> **背景**：当前通用求解器链（aog → rose → pieces → backtrack）对 134 道官方题 FAIL（69 超时
> + 46 无解 + 12 OOM + 7 校验失败），根因是通用求解器不理解某些规则，只在事后验收而不能在搜索
> 中利用规则约束剪枝。本文提出 7 个**规则感知的专用求解器**，每个针对一种高频规则组合，嵌入
> 现有路由作为前置求解阶段。
>
> 更新日期：2026-08-07

---

## 0. 一句话结论

**通用链无法解出的 134 道题可按规则组合聚类为 7 个靶点。每个靶点设计一个轻量专用求解器（独立
模块，≤400 行），作为现有链的前置阶段：专用求解器解出则直接返回，反之回退现有链——零回归风险。
第一波（FenceSolver + SolitaryGrower + DiffAreaGraph）预计新增 30-40 道 PASS。**

## 2. 通用链为什么失败：根因分析

### 2.1 各求解器对规则的支持矩阵

| 规则 | aog | pieces | backtrack | rose | 问题 |
|---|---|---|---|---|---|
| **fence** | ⚠️ 部分 | ❌ 不理解 | ❌ 事后验收 | ❌ 不支持 | backtrack 产出的划分 30s 后被 validate 拒绝 → 7 道校验失败 |
| **ring/brick** | ✅ 搜索中检查 | ❌ 不理解 | ⚠️ 增量检查+事后 | ❌ 不支持 | 边界度约束只在事后确认，不主动推导边状态 |
| **rose_window + same/different** | ⚠️ 3s 预算 | ❌ 不理解 | ❌ 事后验收 | ❌ 拒掉 same/different | 玫瑰窗最有效的求解器被跳过 |
| **solitary** | ⚠️ 部分 | ❌ 不理解 | ❌ 事后验收 | ❌ 不支持 | backtrack 自由生长，频繁产出多 clue / 零 clue 区域 |
| **non_block** | ✅ 搜索中检查 | ❌ 不理解 | ❌ 事后验收 | ❌ 不支持 | backtrack 频繁产出矩形区域被 leaf 拒绝 |
| **difference/inequality** | ✅ 搜索中检查 | ⚠️ 事后验收 | ⚠️ Bellman-Ford (默认关) | ❌ 不支持 | 面积约束传播默认关闭，预搜索阶段空缺 |
| **watchtower** | ✅ 搜索中检查 | ⚠️ 事后验收 | ⚠️ 增量检查+事后 | ❌ 不支持 | 仅在叶子检查，不指导搜索 |
| **different** | ✅ 搜索中剪枝 | ❌ 事后验收 | ❌ 事后验收 | ❌ 不支持 | pieces/backtrack 只在最后查 shapes 集合大小 |
| **puzzle_piece** | ✅ 搜索中检查 | ⚠️ 仅全铺满 | ❌ 事后验收 | ❌ 不支持 | 167/171 道 backtrack 不理解拼块形状约束 |

### 2.2 核心矛盾

通用求解器（backtrack/pieces/rose）的设计哲学是**「先构造完整划分，再检查规则」**。这对 fence、
solitary、non_block 等**全局形状/边界约束**是致命的——backtrack 可能花 30s 构造一个覆盖，然后
validate 说「围栏不对」「有矩形」「形状重复」→ 继续搜下一个 → 超时。

**解决思路**：把规则检查**前置到搜索过程中**，用规则约束**指导**搜索方向而非事后过滤。

## 3. 七个专用求解器设计

### 3.1 架构原则

1. **增量部署**：每个专用求解器是独立模块（`rsolver/src/solver/xxx.rs`），作为现有链的**前置阶段**
2. **独立预算**：专用求解器先跑 5-10s，超时/解不出 → 回退现有链（零回归）
3. **规则签名路由**：`mod.rs` 按规则组合选择专用求解器队列
4. **可开关**：环境变量 gating（如 `FENCE_SOLVER=1`），方便 A/B 测试

### 3.2 路由设计

```
solve(puzzle):
    1. 分析规则组合 → 规则签名
    2. 按签名选择求解器队列：

    签名                                    求解器队列
    ─────────────────────────────────────────────────────────
    fence (+ring/brick/solitary)           FenceSolver → aog → backtrack
    rose_window + same/different           RoseShapeSolver → rose → backtrack
    rose_window + puzzle_piece             RoseShapeSolver → aog → backtrack
    ring + brick + fence                   BoundaryCSP → FenceSolver → aog → backtrack
    ring + brick (no fence)                BoundaryCSP → aog → backtrack
    solitary (±area)                       SolitaryGrower → backtrack
    difference + inequality (+precise)     DiffAreaGraph → backtrack
    non_block ± area                       NonBlockFilter → backtrack
    watchtower + other                     WatchtowerPreFilter → aog → backtrack
    pure rose_window (large grid)          rose (current, OK)

    fallback                                aog → rose → pieces → backtrack (current chain)
```

### 3.3 专用求解器 #1：FenceSolver（围栏感知区域生长）

> **⚠️ 2026-08-08 证伪更新**：下方「阶段 1 DSU 预合并 NonBoundary 边」的核心假设**已被证伪**。
> `fence_pattern` 约束的是该格周围 boundary **形状的 dihedral 规范类**（`validate.rs` 的 fence
> arm 用 `dihedral_key` 比对整个区域形状 vs pattern），**不固定具体哪条边**是 Boundary/NonBoundary。
> pattern 经旋转/反射规范化后 arm 方向不固定——两个相邻 fence 格对共享边的 arm 位置视角可合法
> 不同（实证：puzzle 0390 合法题）。因此：
> - **DSU 预合并不成立**——不能从 pattern 推导 NonBoundary 边。
> - 独立 fence 求解器相比 backtrack 已有的 `check::check_fence_patterns`（cd40cab，dihedral 增量
>   剪枝）**无信息优势**。
> - 已实现的原型（分支 `fence-anchor-bfs`）基于此错误前提，0390 上误判矛盾，未合 main。
>
> fence 方向暂搁。`cd40cab` 的中搜索剪枝（+1 PASS、消 8 校验失败）是已落地的正确收益。
> 详见记忆 [[fence-pattern-dihedral-not-per-edge]]。下方原文保留作历史参考，**勿照此实现**。

**目标**：`fence` 规则（35 道 FAIL，含 7 道校验失败——最高优先级）

**当前失败原因**：
- backtrack 的 `check_global_constraints` 不检查 fence，完全依赖 `validate.rs` 事后验收
- 回溯花 30s+ 找到一个覆盖 → validate 判定 fence 违规 → 继续搜 → 超时或 30s 后报"校验失败"
- fence 格上的 pattern 明确指定了**该格周围 4 条边的边界状态**，但回溯完全不用这个信息

**算法**：

```
阶段 1：预计算（搜索前，O(N)）
  对每个有 fence_pattern 的格：
    - pattern 中 (0,1) 有标记 → 上边 = Boundary
    - pattern 中 (2,1) 有标记 → 下边 = Boundary
    - pattern 中 (1,0) 有标记 → 左边 = Boundary
    - pattern 中 (1,2) 有标记 → 右边 = Boundary
    - 没标记的方向 → 该边 = NonBoundary（必须与相邻格同区域，或外边界/blocked）
  
  传播到共享边的相邻格：
    - 格 A 说 AB 边是 NonBoundary + 格 B 的 fence 说 AB 边是 Boundary → 矛盾，直接无解
    - 格 A 的 fence 没约束 AB 边 + 格 B 说 AB 边是 NonBoundary → AB = NonBoundary
  
  将推导出的边界状态注入 Edge.is_boundary（临时设置，求解器内部使用）

阶段 2：区域生长（搜索中）
  1. fence 格 = 区域锚点，从每个 fence 格开始 BFS 生长
  2. 每次将格加入区域时，增量检查该格的 fence_pattern：
     - 维护每格的当前边界位（4 方向中哪些已确定是 Boundary/NonBoundary）
     - 如果当前状态与 fence_pattern 要求冲突 → 立即剪枝
  3. 与 ring/brick 联动：
     - fence 预计算已确定大部分边的状态
     - 顶点边界度未知数大幅减少 → ring/brick 检查更早触发

阶段 3：回退
  如果 fence 确定的区域生长走不通 → 回退 aog → backtrack（现有行为）
```

**代码位置**：新增 `rsolver/src/solver/fence.rs`

**预计收益**：7 道校验失败 → 全部转无解或解出（不再产出错解）；fence + ring 组合预计算消掉 ≥50% 边界未知数

### 3.4 专用求解器 #2：RoseShapeSolver（带形状约束的玫瑰窗）

> **✅ 2026-08-08 部分落地**：`rose_window + puzzle_piece` 子方向已由 `rose-pp-pin` 实现
> （`rose/puzzle_piece_pin.rs`：预钉 shape_pattern 区域 + region_match 求剩余）。
> 0732 由 rose 解出（+1 PASS，0 回归）。详见 `docs/rust-solver/07-rose求解器.md` §3.1。
> `rose + same` / `rose + different` 子方向仍待实现。

**目标**：`rose_window + same`（4 道）+ `rose_window + different`（3 道）+ `rose_window + puzzle_piece`（3 道）= **10 道纯超时题**

**当前失败原因**：
- `is_rose_capable()`（`mod.rs:238-244`）遇 `same`/`different` 返回 false → rose solver 被跳过
- aog 对 rose 题只有 3s 预算（`AOG_ROSE_BUDGET_MS`）→ 不够
- backtrack 不理解玫瑰窗，30s 构造覆盖 → validate 拒绝 → 超时

**算法**：

```
子问题 A：rose + same（全同形）
  1. 用 rose solver 的候选生成逻辑（MRV BFS + 边界规避）
     生成每个符号种子周围的所有合法候选区域
  2. 过滤：只保留面积为 total_fillable / M（M = 区域数 = 每种符号的出现次数）的候选
  3. 对每个候选计算 dihedral_key
  4. 从所有候选中选 M 个，要求：
     a. 两两不重叠（精确覆盖）
     b. 形状键全部相同（same 约束）→ 所有行必须使用同一个形状
     c. 每个区域包含每种符号恰好 1 个（rose_window 约束）
  5. 编码为带辅列的 DLX：
     - 主列：所有格（精确覆盖）
     - 辅列：每个候选形状键（每个形状键要么全选要么全不选 → same 约束）
     - 行：每个合法候选放置

子问题 B：rose + different（全相异）
  1. 同上生成候选
  2. 编码为带辅列的 DLX：
     - 主列：所有格（精确覆盖）
     - 辅列：每个形状键（每个形状键最多选 1 次 → different 约束）
     - DLX 的 secondary column 语义恰好是 "at most once"

子问题 C：rose + puzzle_piece（形状预确定）
  1. 每个 puzzle_piece 格已有 shape_pattern → 区域形状已知
  2. 枚举 shape_pattern 的 dihedral 变体（≤8 个）
  3. 以 puzzle_piece 格为锚点，反算每个变体占据的格集（固定放置）
  4. 过滤：放置必须包含该 puzzle_piece 格所在符号的所有类型（每种恰好 1 个）
  5. 固定放置加入 DLX（不带旋转/反射，形状已确定）
  6. 其余格用正常候选生成
  7. DLX 求解（带或不带辅列，取决于是否有 same/different）
```

**代码位置**：新增 `rsolver/src/solver/rose_shape.rs`

**预计收益**：10 道纯超时题 → 预计 6-8 道解出（候选数可控的前提下）

### 3.5 专用求解器 #3：BoundaryCSP（基于边变量的约束满足）

**目标**：`ring` (28) + `brick` (18) + `fence` (35) 的三重覆盖，约 **50 道 FAIL**

**当前失败原因**：
- Ring 和 brick 只在搜索中事后检查边界度数，从不主动推导边的状态
- 实际上 ring + brick + fence 组合对边界图的约束极强：
  - 每个顶点度数 ≠ 3 (ring) 且 ≠ 4 (brick) → 只能是 0, 1, 2
  - GF(2) 约束：每个顶点度数为偶数（拓扑定理）→ 只能是 0 或 2
  - 综合：**每个内部顶点的边界度必须恰好是 0 或 2**
  - fence 固定了 fence 格周围的边状态
  - 综合起来，大量边的状态被唯一确定

**算法**：

```
阶段 1：构建边变量图
  变量：每条内部边 e ∈ {Boundary, NonBoundary}（布尔变量）
  顶点：每个网格顶点 (vr, vc)
  边：4 条网格边交汇于每个顶点

阶段 2：编码约束
  a. 顶点度约束（每顶点）：
     - GF(2)：sum(4条边) ≡ 0 (mod 2)    [始终成立，拓扑定理]
     - Ring：sum(4条边) ≠ 3
     - Brick：sum(4条边) ≠ 4
     → 综合：sum ∈ {0, 2}（有 ring+brick 时）
  
  b. fence 约束（每 fence 格）：
     - 上/下/左/右边 = pattern 指定值（0 或 1）
  
  c. 外边界：网格外圈始终是 Boundary
  
  d. blocked 格：blocked-blocked 交界的边 = NonBoundary
     blocked-普通格交界的边 = Boundary

阶段 3：弧一致性传播
  对每个顶点：
    - 已确定 Boundary 数 = k
    - 已确定 NonBoundary 数 = u
    - 未确定数 = 4 - k - u
    - 如果 k == 2 且 ring+brick → 剩余边必须是 NonBoundary（否则度数 ≥3）
    - 如果 k == 1 且 ring+brick → 剩余 3 条中恰有 1 条是 Boundary（度数 = 2）
    - 如果 k == 0 且 ring+brick → 剩余 4 条中恰有 0 或 2 条是 Boundary
    - GF(2) 奇偶：如果 3 条边确定（2B+1N → 奇数 → 第 4 条必须是 B）
  迭代传播到不动点

阶段 4：分支搜索（如果传播后仍有未定边）
  1. 选未定边最少的顶点做分支
  2. 枚举该顶点的合法边界分配
  3. 对每种分配，传播约束，递归
  4. 每个完整的边界分配 → 提取连通区域
  5. 用 validate.rs 验收非边界约束（area, shape, rose_window 等）

阶段 5：回退
  CSP 超时或内存溢出 → 回退 aog → backtrack
```

**代码位置**：新增 `rsolver/src/solver/boundary_csp.rs`

**边界度约束对照表**：

| Ring | Brick | GF(2) | 合法度数 |
|---|---|---|---|
| ✅ | - | ✅ | 0, 2（偶数且 ≠3） |
| ✅ | ✅ | ✅ | 0, 2（偶数且 ≠3,≠4） |
| ✅ | - | - | 0, 1, 2, 4（只要 ≠3） |
| - | ✅ | ✅ | 0, 2（偶数且 ≠4） |
| - | ✅ | - | 0, 1, 2, 3（只要 ≠4） |

**预计收益**：对 `brick+fence+ring`（4 道），fence 预计算 + 传播 ≈ 唯一确定边界；ring+rose（3 道）边界约束大幅缩小 rose 候选空间

### 3.6 专用求解器 #4：SolitaryGrower（独居锚点区域生长）

**目标**：`solitary` 规则（12 道 FAIL）

**当前失败原因**：
- backtrack 不理解 solitary——它自由选择"加入相邻区域"或"开新区域"
- "开新区域"太多 → 有些区域没有 clue 格 → leaf 被拒
- "加入相邻区域"太多 → 有些区域有 2 个 clue 格 → leaf 被拒
- 反复尝试不同分配 → 超时

**算法**：

```
阶段 1：识别锚点
  收集所有 clue-bearing 格（symbol / shape_pattern / fence_pattern / compass / number 任一非空）
  → K 个区域锚点 = K 个最终区域（每个区域正好 1 个 clue 格）
  如果某区域有 ≥2 个 clue 格或某区域 0 个 → 不可满足，直接返回

阶段 2：锚点区域同时生长
  1. 初始化：K 个区域各包含 1 个锚点格
  2. 维护每个区域的前沿（与当前区域相邻的未分配格，BFS 可达且不跨边界）
  3. 每步：
     a. 计算每个未分配格的"候选锚点集合"（BFS 可达的锚点）
     b. MRV：选候选集合最小的格
     c. 对每个候选锚点，尝试将该格分配给该锚点的区域
     d. 增量检查：面积上界、区域形状约束、ring/brick 顶点度
  4. 所有格分配完毕 → 验证全局约束 → 成功

优化：Voronoi 启发式
  对每个未分配格，预计算到各锚点的最短路径
  → 优先尝试最近的锚点（减少搜索分支）
  → 被边界阻断的锚点不可达
  → 如果某格只能到达 1 个锚点 → 唯一确定（强制分配）

与其他规则组合：
  - solitary + area：锚点格携带 area number → 目标面积已知 → 生长到目标面积即停止
  - solitary + differentiation：区域面积各不同 → 面积分配必须互异
  - solitary + fence：fence 格就是锚点 → FenceSolver 的结果可直接喂入
```

**代码位置**：新增 `rsolver/src/solver/solitary.rs`

**预计收益**：12 道 FAIL → 预计 6-8 道解出。锚点数 = 区域数，无需犹豫"开新区域 vs 加入"，搜索分支大幅减少

### 3.7 专用求解器 #5：DiffAreaGraph（差值/不等号面积约束图）

**目标**：`difference` (13) + `inequality` (7) = **20 道 FAIL**

**当前失败原因**：
- Bellman-Ford 传播默认关闭（`BF_PROPAGATE=1` 才启用）
- 即使开启，也只是 mid-search 传播，**没有预搜索阶段**
- 面积约束图在搜索前就能推导出确定性信息

**算法**：

```
阶段 1：预搜索面积推导
  如果有 precise=P 且 N = 总格数：
    - K = N / P（区域数）
    - 每个区域面积恰好 = P
    - 问题退化为：在面积约束图上做一致性传播（所有变量值已知）

  如果区域数 K 已知（如 solitary → K = clue 格数）：
    - 变量：x_1, ..., x_K（每个区域的面积）
    - 约束：
      · sum(x_i) = N（总格数约束）
      · min_area ≤ x_i ≤ max_area（范围约束）
      · difference 边：|x_a - x_b| = d
      · inequality 边：x_a < x_b 或 x_a > x_b
      · area number 格：x_i = n（该格所在区域的面积）
    - 用整数约束求解枚举所有可行面积分配
    - 如果可行方案唯一 → 面积完全确定

阶段 2：集成到回溯
  1. 预计算所有可能的面积分配方案列表 S
  2. 回溯时维护 S 的活跃子集（与当前部分赋值一致的方案）
  3. 当区域密封（frontier 为空）→ 检查其面积：
     - 从 S 中删除所有与该面积不符的方案
     - 如果 S 变空 → 剪枝
  4. 当某区域面积已超过 S 中所有方案的对应值 → 剪枝

阶段 3：回退
  区域数未知或面积方案过多 → 回退 aog → backtrack（现有链）
```

**与现有 Bellman-Ford 传播的关系**：
- 现有 `BF_PROPAGATE=1` 的 Bellman-Ford 是 mid-search 增量传播（每 256 步）
- 本文的 DiffAreaGraph 是**搜索前的全局推导**，互补而非替代
- 建议：DiffAreaGraph 作为预搜索 + Bellman-Ford 默认开启作为 mid-search 补充

**代码位置**：新增 `rsolver/src/solver/diff_area.rs`；修改 backtrack 使用方案约束

**预计收益**：20 道 FAIL → 预计 8-10 道解出。对 precise + difference 组合（面积已知）效果最好

### 3.8 专用求解器 #6：NonBlockFilter（非矩形形状预枚举）

**目标**：`non_block` 规则（18 道 FAIL）

**当前失败原因**：
- backtrack 不理解 non_block——它自由生长区域，经常产出矩形区域
- 矩形区域被 leaf 的 `check_global_constraints` 拒绝 → 回溯 → 再产出矩形 → ...
- 反复尝试直到超时

**算法**：

```
阶段 1：预枚举非矩形 polyomino
  对每个可能的区域面积 a（从 area_bounds）：
    枚举所有面积为 a 的 polyomino（用 polyomino.rs）
    过滤：用 is_rectangle() 排除矩形
    → 得到面积为 a 的所有非矩形形状集合 shapes[a]

阶段 2：形状放置搜索
  将回溯的"自由生长"改为"形状选择"：
  1. MRV 选未分配格（同现有 backtrack）
  2. 如果"开新区域"：
     - 遍历可能的面积 a ∈ [min_area, max_area]
     - 遍历 shapes[a] 的所有 dihedral 变体
     - 以当前格为锚点放置每个变体（try_place）
     - 有效放置加入候选
  3. 如果"加入现有区域"：
     - 同现有回溯逻辑，但加入后检查：区域的当前格集能否扩展为某个非矩形形状的子集
  4. 形状一旦确定 → 区域格集完全确定 → 没有"自由生长"的不确定性

优化：面积上界限制
  如果 max_area ≤ 8 → polyomino 枚举量可控（≤ 369 种）
  如果 max_area > 8 → 仅对面积上界过滤，不预枚举（回退自由生长 + post-check）
```

**代码位置**：新增 `rsolver/src/solver/non_block.rs`（复用 pieces.rs 的放置枚举逻辑）

**预计收益**：18 道 FAIL → 预计 5-8 道解出（max_area ≤ 8 的题效果最好）

### 3.9 专用求解器 #7：WatchtowerPreFilter（望塔角点约束传播）

**目标**：`watchtower` 规则（16 道 FAIL）

**当前失败原因**：
- watchtower 是全局顶点约束，只在 leaf 检查
- 如顶点 (vr,vc) 有 watchtower=3：周围 4 格分属 3 个不同区域
  → 恰好 2 格同区域，其余各属不同区域 → 明确的局部约束
- 当前完全不用这个信息指导搜索

**算法**：

```
阶段 1：局部枚举
  对每个有 watchtower 的顶点 (vr,vc)，目标值 = T：
    枚举周围 4 格（跳过 blocked）的合法区域划分：
      - 恰好 T 个不同区域
      - 同区域格必须 4-连通（直接相邻或通过未被其他 watchtower 约束的格间接连通）
      - 不跨预画边界
    存储所有合法划分方案 plans[vr][vc]

阶段 2：约束传播
  相邻 watchtower 顶点共享格子：
    - 格子 (r,c) 同时属于顶点 A 和顶点 B 的周围格集合
    - 合并 A 和 B 的合法方案：只保留在共享格上一致的方案对
  
  迭代合并直到不动点 → 全局一致的局部方案集合

阶段 3：搜索中剪枝
  回溯过程中：
    - 当 watchtower 顶点周围的格被赋值 → 检查是否还在 plans[vr][vc] 中
    - 如果某顶点已有 T 个不同区域的格被赋值 → 其余格必须属于这些区域之一
    - 如果 plans[vr][vc] 变空 → 剪枝
```

**代码位置**：新增 `rsolver/src/solver/watchtower_pre.rs`

**预计收益**：16 道 FAIL → 预计 3-5 道解出。密集 watchtower 题（如 0985/0543）效果最好

## B. 实施记录

### B.1 第一波实施（2026-08-07，commit `be8ae97` → WIP）

实施了 4 项低风险优化，均嵌入现有搜索框架而非新增求解器模块：

#### 改动 1：约束边强制为边界（`rsolver/src/io.rs`）

**改动**：在 `build_puzzle` 解析边时，对 inequality / difference / heterogeneous /
homogeneous 边自动设置 `is_boundary = true`。

**原理**：这些边约束要求两侧格属于不同区域，因此该边必然是边界。之前只有 aog 求解器
在内部编码时做了这个转换（`core.rs` LINE_BLOCK），backtrack / pieces / rose 不感知。
现在统一在解析阶段设置，所有求解器通过 `is_adjacent_free()` / `is_precut()` 自动受益。

**代码量**：~10 行

#### 改动 2：回溯中密封区域形状规则即时检查（`rsolver/src/solver/backtrack.rs`）

**改动**：新增 `check_sealed_regions()` 函数，在每次 `frontier_assign` 后调用。
当一个区域密封（frontier 为空，形状已确定）时，立即检查 different / same / block /
non_block 约束，而非等到全部格分配完毕后的叶子检查。

**设计要点**：
- 无状态设计：不维护持久化的已密封形状集合，每次调用从 `region_shapes` 和
  `frontier` 重新计算。这样不需要 undo 逻辑。
- 只对已密封区域检查（`is_sealed()` = frontier 为空），未密封区域跳过。
- `different` 和 `same` 互斥（`CONFLICTING_RULES`），使用 `if/else if` 避免
  borrow checker 问题。

**代码量**：~55 行

#### 改动 3：Bellman-Ford 面积传播默认开启（`rsolver/src/solver/prototypes.rs`）

**改动**：`propagate_area_bounds` 的 gate 从 `BF_PROPAGATE=1`（opt-in）改为
`BF_PROPAGATE=0`（opt-out，默认开启）。

**影响**：每 256 步在回溯中用 Bellman-Ford 传播 inequality / difference 边的面积约束。
对 inequality（7 道 FAIL）和 difference（13 道 FAIL）题有效。

**代码量**：2 行

#### 改动 4：搜索前拓扑校验（`rsolver/src/solver/mod.rs`）

**改动**：新增 `pre_search_topology_check()`，在所有求解器运行前做 O(V) 扫描，检查预画
边界是否已经违反 ring / brick 约束。

**⚠️ BUG 教训（三次迭代）**：

**Bug 1 — 数组边界越界**（已修复，exit code 101 panic）：
初版访问 `h_edges` / `v_edges` 时边界检查有误。
- `h_edges[r][c]` 维度 `[h][w-1]`：边在 `r` 行，连接 `c` 列和 `c+1` 列，列索引必须 `c+1 < w`。
- `v_edges[r][c]` 维度 `[h-1][w]`：边在 `c` 列，连接 `r` 行和 `r+1` 行，行索引必须 `r+1 < h`。
- 用 `c < w` 访问 `h_edges` 或 `r < h` 访问 `v_edges` 会越界 panic。

**Bug 2 — 外边界过度计数**（已修复，8 道误判）：
初版在网格角落顶点（如 `(0,0)`）错误地把两条"两面都不邻接网格格"的边也计为边界。
正确做法：顶点 (vr,vc) 的四条边中，**两面都有网格格**才是内部边（检查 `is_boundary`），
**恰好一面有网格格**才是外边界，**两面都没有**（角落外侧）不计为边界。

**Bug 3 — Ring 拒绝阈值过于激进**（已修复，2 道误判）：
Ring 规则禁止度数恰好为 3。当确定性边界数 `def_boundary == 3` 但还有未知边
（`unknown > 0`）时，最终度数可能是 4（ring 允许，4≠3），不能预判。正确阈值：
- Ring：`def_boundary == 3 && unknown == 0`（所有边已确定，正好 3 条边界→违反）
- Brick：`def_boundary >= 4`（确定性 ≥4，最终肯定 ≥4→违反）

**最终实现**：用正确的单元格几何（`(vr-1,vc-1),(vr-1,vc),(vr,vc-1),(vr,vc)` 四个角格）
判断每条边的状态，只对确定的边界计数，区分 `def_boundary` 和 `unknown`，使用修正后的阈值。

**代码量**：~40 行

#### 改动 5：移除 BacktrackState 死方法（`rsolver/src/solver/backtrack.rs`）

`propagate_area_bounds` 重构为接收独立参数后，`BacktrackState` 的
`next_region_id()` / `region_shapes()` / `region_size()` / `cell_region()` 方法
变为死代码，已移除。仅保留 `is_sealed()`（被 `check_sealed_regions` 使用）。

**代码量**：-15 行

### B.2 FenceSolver 嵌入实现（2026-08-07，专用求解器第一波 #1）

实施了 §3.3 FenceSolver 的**内嵌变体**：不新建独立求解器模块改路由，而是把 fence
检查作为搜索中增量约束嵌入现有 backtrack。架构上独立成 `solver/fence/` 文件夹（仿 `rose/`），
但实际搜索仍走 backtrack——因为 fence 题大多带伴生规则（area/ring/brick/homogeneous），
复用 backtrack 的全部约束能力比重写一套独立 region-grower 更省且更强。

#### 架构

```
rsolver/src/solver/fence/
  mod.rs     // FenceCellData{r,c,arm_count,pattern_dihedral_key} + build_fence_cells(puzzle)
  check.rs   // check_fence_patterns(puzzle, cell_to_region, width, fence_cells) -> bool
```

- `validate.rs`：`fence_pattern_shape` 改 `pub(crate)`，供 backtrack 复用，保证 cross 构造
  与 leaf validator 字节一致（避免 dihedral_key 漂移）。
- `backtrack.rs`：`BacktrackState` 加 `fence_cells` + `has_fence` 字段；`solve_backtrack`
  构造时调 `fence::build_fence_cells`；守卫链两处加 `check_fence_ok`（薄转发，解耦
  `fence` 模块与 `BacktrackState` 类型）。

#### 核心算法（soundness 要点）

`fence_pattern` 是**逐格**约束：每个带 pattern 的格指定其 4 方向边界位（dihedral 归一化）。
关键正确性：`dihedral_key` 对**完整**点集归一化，半成品形状的 key 无意义——所以 dihedral
比较只在 **4 边界位全定时**做。bit 判定表（与 `validate::region_boundary_bits` 一致）：

| 邻居状态 | bit | 确定? |
|---|---|---|
| 越界 / blocked | true | 是 |
| 已分配到 `n_rid` | `n_rid != my_rid` | 是 |
| 未分配 + 间边 `is_boundary` | true | 是（`is_adjacent_free` 禁跨此边合并） |
| 未分配 + 间边非 `is_boundary` | 未知 | 否 |

**arm-count 部分检查**（未全定也剪）：`k = fp.len()-1` 是 dihedral 不变量。设 T=已定 true 数、
F=已定 false 数、U=4-T-F。最终 true 数 ∈ [T, T+U]，必须等于 k：
- `T > k` → 必然不匹配 → 剪
- `F > 4-k`（即 T+U < k）→ 必然不匹配 → 剪

对 k=0（4 边全非边界，任一已定 true 即剪）和 k=4（4 边全边界，任一已定 false 即剪）杀伤最大。

无状态设计（仿 `check_sealed_regions`），无 undo 逻辑；`has_fence` 门控让非 fence 题零开销。

#### 结果（vs `6169df3` 基线，40s）

- **0 回归，+1 PASS（0829）**；fence 子集 171 题 PASS 数 127→127（搜索空间仍太大）。
- **8 道校验失败 → 0**：backtrack 不再产出 fence 错解，失败模式转无解/超时/OOM。

#### 收益局限与下一步

内嵌剪枝消除了错解但没加速到找到正解——fence 题搜索空间太大，剪枝不足以在 40s 内搜完。
要找正解需更强的搜索引导，即 §3.3 阶段 1 的**边界预推导 + 传播**：

- fence_pattern 共 6 个 dihedral 类。**k=0/k=4**（104 格）搜索前全 4 边定；
  **k=2 对臂**（318 格）已知任意 1 边即全 4 边定（用户洞察）；k=1 知 1 边界即全定；
  k=3 知 1 非边界即全定。
- 种子来自外边界（边缘格外侧边恒为 Boundary）→ 触发该格全定 → 向内级联传播。
- 确定的 **NonBoundary 边**两端格必同区域，可用 DSU **合并为原子单位**（用户洞察），
  直接缩小搜索空间（格数 ↓ → 分支数指数级 ↓）。
- 阻塞项：`solve(&Puzzle)` 不可变借用需改 `solve(mut puzzle: Puzzle)`（单调用点 main.rs，低风险）；
  `is_boundary: bool` 二态 conflates「未定」与「NonBoundary」——NonBoundary 走 DSU 合并
  而非写 `is_boundary=false`，可规避三态 Edge 改动。
