## 0. 一句话结论

第二轮调研在 4 个新维度发现 22 个独立优化点，其中 **7 个"白捡"级零风险小改动**（env 缓存、
编译 profile、check_radar 守卫、合并 collect、can_partition 跳过、batch 默认值、slash_dist 预分配）
可立即落地；**3 个高 ROI 算法项**（K-bounding 85 题、惰性面积组合、多符号 BFS 剪枝）预计解出
8-15 道。**最重要的发现**：aog 求解器完全没利用区域数 K——85 道 FAIL 题（41.3%）的 K 可精确
锁定（precise/solitary/rose_window），但 aog 从不检查 `index <= K`，这是本轮最高 ROI 项。

## 2. P0 高 ROI 算法（3 项，预计 8-15 道）

### A1. K-bounding：aog 限制区域数 ≤ K（最高 ROI，85 题）

**发现**：precise/solitary/rose_window 规则下 K 可精确锁定（13 号已归纳，但求解器没用）：
- precise: K = fillable / N（172/172 验证）
- solitary: K = 被计线索格数（87/87 验证）
- rose_window: K = 符号出现次数（182/182 验证）
- 合计 424/1229（34.5%）官方题可锁定 K；**206 FAIL 中 85 题（41.3%）K 可锁定**（rose 56 + solitary 23 + precise 6）。

**现状**：aog 全目录无 `region_count`/`num_regions` 变量。`dfs(index)` 的 `index` 是深度但从不检查 `≤ K`。终止条件是"无空格"而非"放满 K 个区域"。rose solver 内部用了 K（`rose/mod.rs:22-41`），但 aog/backtrack 没用。

**方案**：`core.rs:build_config_from_rules` 计算 `max_regions: Option<usize>`；`search.rs:851 dfs(index)` 入口加 `if max_regions.is_some() && index > max_regions { return -1 }`；`empty.rs:empty_area_check` 加 K 一致性校验（剩余空区数 < K-index 个最小区域 → 剪枝）。

**收益**：85 题 K 可锁，其中 43 timeout + 35 no_solution。aog 当前放任形状数增长到任意多区域，K-bounding 直接砍掉超 K 的分支。预计解出 **5-12 道**。
**难度**：小（~20 行）。**风险**：低（只增上界检查）。**依赖**：无。

### A2. enum_area_combos_bounded 改惰性流式（2-4 timeout）

**发现**：`region_match.rs:268` 把所有面积组合预收集到 `Vec<Vec<usize>>` 再排序遍历。对大 m 题：
- 0804 (m=9): ~10 亿组合；0223 (m=31): ~1.7e28；0882 (m=22): ~2.2e20。
- `PER_COMBO_TIMEOUT_MS=1000` 失效——组合先生成后迭代，生成阶段本身就超时/OOM。

**方案**：改为惰性/流式生成器，递归函数调回调，每个组合生成后立即试 `match_regions_mrv`，成功或超时即返回。消除 `Vec<Vec<usize>>` 分配，支持提前终止。

**收益**：直接修 2-4 timeout（C4-2 m=6 / 1433 m=4 / 1434 / 0804 临界）。**难度**：低-中（~50 行）。**风险**：低（纯控制流）。

### A3. 多符号 BFS 收集全符号后停止扩展（2-4 timeout）

**发现**：`region_match.rs:83-131` 多符号 BFS 探索所有连通子集，只保留含全符号类型的。但收集到全符号后**继续扩展**（:100-131），产生更大候选消耗 visited/队列预算。`VISITED_CAP=200000` 常在找到足够候选前触发。

**方案**：候选加入 results（:95）后若 `syms == all_required`，**不再入队后继**（`continue`）。更大超集无益（占更多网格、与 total/m 平衡性更差）。

**收益**：多符号题 visited/队列缩减 10-50 倍，推迟 VISITED_CAP 触发。修 2-4 timeout（C4-2 st=3 / 0620 st=3 / 1433 st=2）。**难度**：极低（~10 行）。**风险**：低-中。

## 5. compass 连通性面积下界闭式解（补 13 号文档"未推完"方向）

> 13 号 §4 标注"连通性约束未纳入，下界还能更紧"。本轮推导出正确闭式解。

**公式**：当 U,D,L,R 全非 -1 时：
```
面积 = 1 + U+D+L+R - overlap
overlap = 对角格数（NW/NE/SW/SE 四象限的格）
max_overlap = min(U+D, L+R)
若 U+D == L+R 且 max_overlap > 0：max_overlap -= 1   // 全对角时无轴线格→不可能
improved_LB = 1 + U+D+L+R - max_overlap
```

**关键洞察**：对角格需经轴线格（上下/左右方向的格）连接到线索格。一条轴线可连接多个对角格，
所以对角格不需要各自独立的轴线格。之前的错误尝试 `max(0,U-1)+max(0,D-1)` 违反 38 个线索，
因为它假设每个对角方向需独立轴线。

**验证**：971 线索 0 违反，28 线索比原 `1+U+D+L+R` 更紧，7 线索 gap 完全闭合。
**落地**：aog 预搜索 / edge_csp 的 compass 传播器，~15 行。

## 6. 否定假设（避免重复调研）

| 假设 | 验证结果 | 原因 |
|---|---|---|
| area 数字和 = fillable | **否定**（仅 32/44 题） | 同区域可多 area 格（如 1159 每区域 7 个 area 格，和=343 >> fillable=49）。每格数字==区域面积（1921/1921 ✓）但和因重复计数失真。除非 solitary 同时存在（每区域 1 格） |
| shape_pool K = 池大小 | **否定**（仅 2/236，0.8%） | K 普遍远大于池大小（差值众数 8-13）。shape_pool 是"形状库可复用"非"每区域一形状" |

## 7. 统计发现（指导优化方向）

### 7.1 FAIL 率与规则强相关

| 规则 | FAIL 率 | 极难(>30%) |
|---|---|---|
| ring | 57.7% | ✓ |
| watchtower | 41.2% | ✓ |
| difference | 36.6% | ✓ |
| inequality | 34.7% | ✓ |
| compass | 34.1% | ✓ |
| shape_pool | 1.3% | 极易 |
| precise | 3.5% | 极易 |

**高频 FAIL 规则对**：ring+rose_window(15)、fence+ring(14)、brick+ring(13)、compass+solitary(12)。
**FAIL 集中大盘**：66% FAIL 网格 ≥61 格。

### 7.2 规则互斥（路由指导）

- precise ∩ area = 0（互斥的区域约束范式）→ precise 走 aog（面积已锁），area 走 backtrack/pieces。
- area + shape_pool 几乎互斥（lift=0.14）。
- watchtower=4 ∩ brick = 0（13 号已归纳，可做早期无解检测）。

### 7.3 blocked 格分布

56.5% 官方题含 blocked，64% 在边界、92.7% 距边界 ≤2。但 67% 题含内部 blocked。same 规则 92.5% 与 blocked 共存。

### 7.4 solitary 锚点均匀性

48% solitary 题 CV<0.1（近乎完美均匀），74.5% 锚点在内部。当前 `find_special_start_area` 不直接用锚点作区域种子。
