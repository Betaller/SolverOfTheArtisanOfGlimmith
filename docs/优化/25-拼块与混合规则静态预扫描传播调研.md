## 0. 一句话结论

提议的两条推断**语义上成立**（但第二条只在 `mixed`/`different` 下成立，见 §2.3 反例），
"多次预扫描到不动点"在形式上是边变量 CSP 的单位传播闭包——**但对本语料价值接近 0**：

| 指标 | 数值 |
|---|---|
| 相关题范围（含 `puzzle_piece`/`mixed`/`different`/`same`/`shape_pool`） | 561 |
| 其中"用户这两条推断"能推出至少一条边的 | **19**（17 已 PASS 且全部 ≤26ms，2 FAIL） |
| 加上推广规则（池尺寸域、need-partner 链、封区排斥）后能推出边的 | 202（196 PASS / 6 FAIL） |
| 被触及的 6 道 FAIL 中，cut-only 变体实测被翻转的 | **0** |

**根因：aog 已经在区域落定时增量强制了这两条规则**
（`search.rs:295` `shape_in_puzzle_fail`、`core.rs:238` `check_nearby_shape`），
预扫描提供的不是"新约束"，只是"提前 n 步的闭包"；而 aog 走到同样结论只需 O(1) 个节点。
能完整定盘的题（0287、1151、1416 等）现在本来就是 0~51ms 出解。

**建议：不作为独立优化项实现。** 若要落地，只作为 aog 的前置种子（~100 行、可开关），
预期 +0 题；真正缺的不是"提前知道"，是搜索层面的形状同一性推理（见 §7.2）。

## 1. 提议与形式化

原始提议（两条 + 一条补充）：

1. **大小为 1 的拼块一定是确定的填充方式**（该格自成区域，四边全是边界）；
2. **两个挨着的单元若拼块相同，则肯定是同一个区域**；
3. 补充：**若某单元拼块是 1 格，则与它相邻的单元至少 2 格**；
4. 作题之前可以**多次预扫描**（迭代到不动点）。

形式化：把每对相邻可填格之间的内部边建模为变量 `e ∈ {cut, same, unknown}`
（`cut` = 两侧分属不同区域；`same` = 同区域），反复应用一组可靠（sound）推断直到不再变化，
再把 `cut` 边当作预画边界、`same` 边当作合并约束喂给求解器。

## 2. 语义正确性

### 2.1 规则语义（实现口径）

| 规则 | 语义 | 位置 |
|---|---|---|
| `puzzle_piece` | 若格 `c` 有 `shape_pattern`，则 **c 所在区域**的形状 dihedral key 必须等于 pattern 的 key。注意：只钉**形状类**，`pattern` 的字面摆放位置**不**参与校验 | `validate.rs:181-191` |
| `shape_pool` | 所有区域形状必须来自池 | `validate.rs:80-89` |
| `mixed` | 任意两个**相邻**（共边且中间无边界）区域，形状 key 必须不同 | `validate.rs:127-133` |
| `different` | 全局：所有区域形状 key 两两不同 | `validate.rs:120-126` |
| `same` | 全局：所有区域形状 key 相同 | `validate.rs:113-119` |

### 2.2 推断 1（1 格拼块 ⇒ 四边切）：✅ 正确，且不依赖其它规则

证明：设格 `c` 的 pattern 为 1 格形状。由 `puzzle_piece`，`R = region(c)` 满足
`dihedral_key(R) = monomino`，故 `|R| = 1`；又 `c ∈ R` 且 `R` 连通 ⇒ `R = {c}`。
区域大小为 1 ⇒ `c` 与所有相邻可填格之间的边必为 `cut`。∎

**注意口径**：因为校验只比对形状类，`pattern` 的字面偏移不约束区域位置，
所以只能推出"区域 = `{c}`"这一条，不能推出"pattern 的邻格属于别的区域"之类更强的结论。

### 2.3 推断 2（相邻同拼块 ⇒ 同区域）：⚠️ 只在 `mixed`/`different` 下成立

- **在 `mixed` 下成立**：若 `a`、`b` 相邻且 pattern key 同为 `K`，假设二者分属区域 `R_a≠R_b`，
  则 `key(R_a)=key(R_b)=K` 且两区域相邻，直接违反 `mixed`。故 `same(a,b)`。∎
- **在 `different` 下更强**：只要两个格的 pattern key 相同（**不要求相邻**），就必须在同一区域。
- **在只有 `puzzle_piece`（无 `mixed`/`different`）时不成立**：
  两个分离的区域可以同为 domino——`validate` 完全接受，`aog` 也接受
  （`check_nearby_shape` 只在 `config.adjacent_shapes_different` 为真时才调用）。
  语料里 `puzzle_piece` 共 171 道，其中只有 31 道伴生 `mixed`、13 道伴生 `different`，
  **即推断 2 只在 ≤44 道上可用**，其余 127 道若强行合并会**产生错解**（unsound）。

实现时必须先判规则再启用，`scripts/exp_shape_prescan.py` 的 `R2` 正是用
`mixed or diff` 做守卫。

### 2.4 补充规则（1 格拼块的邻居 ≥ 2 格）：✅ 是推断 1 + `mixed` 的推论

`R={c}` 封区后，其任一邻居格 `x` 所在区域与 `R` 相邻 ⇒（在 `mixed` 下）`key(region(x)) ≠ monomino`
⇒ `|region(x)| ≥ 2` ⇒ `x` 至少要与一个相邻可填格同区。
当 `x` 的"未切边邻居"恰好只剩 1 个时，那条边被强制为 `same`（这就是实现里的 `R4_need_partner`）。
推广：`shape_pool` 中所有形状都 ≥2 格时，该结论对**每个格**成立（1130 即此情形，19 条 `same`）。

## 3. 传播规则集（可反复预扫描到不动点）

`scripts/exp_shape_prescan.py` 实现的规则，迭代直到无变化（实测 0 道题出现矛盾 / unsat=0）：

| 规则 | 内容 | 触发次数（全语料累计格次） |
|---|---|---|
| `R0_pool_domain` | `shape_pool`（减去被 `mixed`/`different` 禁用的 key）给出每格的区域尺寸域；域唯一 ⇒ 钉住尺寸 | 6630 |
| `R1_monomino` | 1 格拼块 ⇒ 该格封区，四边 `cut`（**推断 1**） | 70 |
| `R1_size2` / `R1_comp_seal` | 尺寸已知为 s 的格：连通开分量恰好 s 格 ⇒ 封区；s=2 且只剩一个候选 ⇒ 封区；分量 < s ⇒ 矛盾 | 51 / 32 |
| `R2_same_key_merge` | 相邻同 key 拼块 ⇒ `same`（**推断 2**，需 `mixed`/`different`） | 19 |
| `R3_forbid_key` / `R3b_cut_forbid` | 已封区区域把它自己的形状 key 禁给邻居（`mixed`）或全体（`different`）；已切边两侧同理 | 17 / 91 |

| `R5_consistency` | 封区后的实际形状 key 必须与区内任一被钉 key 一致，否则矛盾 | — |

## 5. 关键：aog 已经增量强制了这两条规则

预扫描的"信息"对 aog 并不新，代码级证据：

| 用户推断 | aog 中的对应强制 | 位置 |
|---|---|---|
| 1 格拼块 ⇒ 区域 = 该格 | 图案格被打上 `AREA_SHAPE_INDEX_BIT`（形状索引钉死）；区域落定时若索引与图案不符 ⇒ `shape_in_puzzle_fail` 剪枝。给 1 格区域加第二格时索引必然变成 domino ⇒ **立刻剪掉**，等价于"四边切" | `core.rs:661`、`core.rs:799-820`、`search.rs:295-299` |
| 相邻同拼块 ⇒ 同区域 | `"mixed" ⇒ config.adjacent_shapes_different = true`（`core.rs:571`）；区域落定时调用 `check_nearby_shape`，相邻同形状索引直接失败 | `core.rs:238-253`（`check_nearby_shape`）、`search.rs:281` |
| 邻居 ≥2 格 | aog 形状目录带 `shape_size_by_index`，`check_nearby_size` 已在 `differentiation` 下做同类比较 | `core.rs:257-276`、`search.rs:284` |

也就是说：aog 在搜索中"试错一次"就能得到预扫描静态推出的结论，代价是常数个节点。
这解释了画像里最刺眼的一点——**被预扫描完整定盘的题（0287/1151/1416）现在 0~51ms 就出解**，
预扫描能省下的是几十微秒，不是搜索量级。

预扫描**唯一**可能带来新信息的是需要多步闭包的部分：
分量封区（`R1_comp_seal`，32 次）、`need-partner` 链（`R4`，917 次）、池尺寸域钉尺寸（`R0`，6630 次）。
这些 aog 的局部增量检查确实看不到——但它们落点几乎全在已经秒解的题上。

## 6. 实测：把预扫描结论喂回求解器

**方法**（`scripts/exp_shape_prescan.py exp`）：把预扫描推出的 `cut` 边写成 `is_boundary` 的
预画边界，用同一份 `rsolver` 二进制（`RSOLVER_TIMEOUT_MS=40000`，wall 预算与 benchmark 同口径
`timeout × RUST_PARTS(4) × SLACK(1.2)`）跑原题（control）与变体（variant）对比。

> 口径限制：puzzle JSON **没有"同区域"边约束类型**（`io.rs:46-51` 只有
> heterogeneous/homogeneous/inequality/difference），所以 `same` 边无法编码，
> 实验只能测 **cut-only 子集**，即**低估**预扫描收益。

> 负载 caveat：本实验运行时另一会话正在跑全量 benchmark（同机 8 路并发），
> wall 时间不可靠；下表以"是否解出"为准（solve outcome），耗时仅作噪声参考。

**结果（24 道预扫描有产出的题）**：

| | control | variant |
|---|---|---|
| 解出 | 22/24 | 22/24 |
| 未解出 | 1435、0994（基线 80s 超时） | 1435、0994（仍超时） |
| 耗时（噪声参考） | 除 0827(27ms)/0368(4ms)/0021(2ms) 外全为 0~1ms | 0827 21ms、0368 4ms、0021 8ms，其余 0~1ms |

- **没有任何一道被翻转**；耗时差异在噪声量级（0021 反而 2ms→8ms）。
- 1435 是最有希望的一道题（预扫描推出 26 条 `cut` + 9 条 `same`、封死 8 个区域，
  未知边从 287 降到 252）；但把 26 条 `cut` 写成预画边界后**仍然超时**——
  说明 156 格 × 13 形状的瓶颈不在这些局部信息上。
- 0994 的变体跑出了完整求解链：`aog`(41s 超时) → `pieces`(40s 超时) →
  `backtrack`(exhausted)，依旧无解——4 条 monomino 封区（预扫描的推断 1 子集）于事无补。

## 7. 结论与建议

### 7.1 是否实现：否（独立优化项）

- 收益上限：19 道靶子题里 17 道已 PASS（≤26ms），2 道 FAIL 实测未翻转 ⇒ **期望 +0 题**。
- 成本：aog 前置 pass ~100 行 + 需要新增"`same` 边"内部表达（aog 目前只有 `LINE_BLOCK`
  这类"必切"标记，没有"必连"标记），且形状索引/边界语义改动面不小。
- 风险：推断 2 若忘了加 `mixed`/`different` 守卫，会在 127 道纯 `puzzle_piece` 题上产生错解（§2.3）。

### 7.2 如果一定要做，正确的形态

1. **只开规则子集**：`R1_monomino` + `R2_same_key_merge`（推断 1、2）+ `R3b_cut_forbid`，
   不需要 `R0`/`R4`（它们主要打在已秒解的题上，且 `R0` 与 aog 的池语义重复）。
2. **落点放在 aog 建盘阶段**（`aog/core.rs` 里 pattern 注册之后）：把推出的 `cut` 边写进
   `h_edges/v_edges.is_boundary`，`same` 边用新的 `LINE_MUST_JOIN` 位表达并在
   `search.rs` 的邻接判断里强制。
3. **开关 + 门禁**：默认关闭；开启后必须跑
   `python scripts/benchmark_rust_solver.py --timeout 40 -j 8 --baseline results/bench/20260902_a8172ff_full.jsonl`
   且 `REGRESSION=0` 才考虑合入（见 [[feedback-merge-gate]]）。
4. **不要**指望它能救 1435/1130/1098-1100/0994。

### 7.3 更有价值的相关方向

- 这轮调研顺带确认：**`shape_pool`/`puzzle_piece` 题被 `edge_csp` 明确排除**
  （`edge_csp/mod.rs:785`），它们的形状约束完全没有进入边传播宿主。
  若要做形状推理，性价比更高的是把"形状同一性/尺寸域"做成 **edge_csp 的传播器**
  （doc 21 的第④档"形状同一性 ~21 道"），而不是在 aog 前面加一层静态预扫描。
- 1130 的 `R4_need_partner` 是唯一在 176 格大盘上还能推出 19 条边的情况，
  若将来 edge_csp 支持形状约束，这条规则值得直接实现为传播器。
