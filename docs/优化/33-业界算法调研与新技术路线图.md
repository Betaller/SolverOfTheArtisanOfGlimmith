## 0. 一句话结论

**关键发现：edge_csp 已吸收参考求解器的全部核心传播技术**（probing / pair probing /
compass 桥/网关 / watchtower 配置探测），剩余 ~28 FAIL 不是缺传播，而是**搜索效率瓶颈**。
业界 2022-2026 最有价值的三项新技术是：**① Lazy Clause Generation（LCG，传播解释→nogood学习→
非时序回跳）**——范式级升级，预期解决剩余根本难问题；**② CBJ + LDS + 重启（轻量搜索增强）**——
低成本高收益；**③ 动态连通性割 + 并行 Portfolio**——补强。其中 ① 是唯一能突破当前天花板的范式，
② 是投入产出比最高的立即可做项。

## 1. 业界新技术全景（2022-2026）

### 1.1 Lazy Clause Generation（LCG）— 混合 CP+SAT 范式

**代表**：[Chuffed](https://github.com/chuffed/chuffed)（MiniZinc Challenge 常年冠军）、Google OR-Tools CP-SAT。

**核心思想**：每个传播器记录**传播解释** `a₁ ∧ ... ∧ aₙ → d`（哪些域事实导致了哪些域变化），
形成蕴含图。矛盾时用 1-UIP 分析学习 **nogood**（冲突子句），实现：
- **非时序回跳**（backjumping）：学习子句中没有的决策层直接跳过
- **VSIDS 变量排序**：按冲突活跃度选分支变量，指数衰减
- **重启 + 保留学习子句**：逃脱无效子树同时积累知识

**与本项目的关系**：
- 我们的 edge_csp 传播器（watchtower/compass/area/ring/brick）都可以输出传播解释
- 当前 DFS 是**时序回溯**（pop 一层），LCG 可跳过多层
- **体量**：~1000 行核心 + 传播器改造
- **预期**：搜索树缩小 10x-1000x（Chuffed 论文数据）
- **风险**：改造面广，需要给每个传播器加解释输出

**优先级**：P1（范式升级，中期投入）

### 1.2 Probing / Failed Literal Detection — 参考求解器已有

**代表**：`third_party/aog` 的 `probe_one_round` / `probe_pair_round`。

**核心思想**：
1. **单探测**：对每条未知边，试 Cut→传播→恢复；试 Uncut→传播→恢复。一边矛盾→强制另一边。
2. **对探测**：共享顶点的边对，试 4 种组合。仅 1 存活→强制该组合。
3. **watchtower 顶点配置探测**：枚举合法配置，仅 1 存活→强制。

**与本项目的关系**：
- 我们的 edge_csp 有 `snapshot/restore` 机制，可以直接实现 probe
- 当前 edge_csp 的传播是"被动检查"（看矛盾就拒绝），probing 是"主动试探"（假设→传播→看结果）
- **体量**：~200-300 行
- **预期**：接近 SAT 单位传播强度，compass 簇和 watchtower 簇直接受益
- **风险**：低（有 snapshot/restore 基础）

**优先级**：**P0（最高 ROI，直接移植）**

### 1.3 CBJ（Conflict-Directed Backjumping）— 轻量搜索增强

**核心思想**：DFS 每个节点维护**冲突集**（导致失败的决策变量集合）。回溯时跳到冲突集中最低层，
而非简单 pop 一层。冲突集在回溯时合并传递。

**与本项目的关系**：
- edge_csp DFS 直接可用
- **体量**：~200 行（每帧一个 SmallBitSet）
- **预期**：跳过无关分支，硬实例搜索树缩小 2-10x
- **风险**：极低

**优先级**：P1

### 1.4 LDS（Limited Discrepancy Search）— 启发式纠错搜索

**核心思想**：启发式"大体正确但偶尔错"时，LDS 先试 0 偏差（纯启发式），再试 1 偏差，逐步放宽。
迭代 LDS（ILDS）从头重启。

**与本项目的关系**：
- 0770 FreeRem 的问题就是"正确答案在候选集但搜索不到"——LDS 直接解决
- **体量**：~100 行
- **预期**：0770 类问题 + compass 簇值序问题
- **风险**：极低

**优先级**：P1

### 1.5 重启 + 学习子句保留

**核心思想**：搜索 N 节点后重启（回到根），保留学习的 nogood。Luby 序列：1,1,2,1,1,2,4,...
Glucose 式：LBD（Literal Block Distance）移动平均超阈值时重启。

**与本项目的关系**：
- 解决"值序差导致真解排很后"的问题（0770 真解排 35000）
- **体量**：~50 行
- **预期**：值序敏感型问题（0770/0308/0838）
- **风险**：极低

**优先级**：P1

### 1.6 并行 Portfolio 搜索

**核心思想**：同时跑多个配置（不同变元序/不同传播器/不同搜索策略），第一个找到解的赢。
Rust `std::thread::spawn` + `AtomicBool` 早停。

**与本项目的关系**：
- 当前 RustSolver 是单线程子进程，有闲置 CPU 核心
- **体量**：~200 行
- **预期**：利用多核，等效于搜索预算翻倍
- **风险**：低

**优先级**：P2

### 1.7 动态连通性割生成（Hashiwokakero branch-and-cut）

**核心思想**：不在预传播中枚举所有连通性约束，而是在搜索中**按需生成**连通性割
（"至少一条边必须 Uncut 保持连通"）。记录哪些边赋值导致断连，学习禁止该组合。

**与本项目的关系**：
- 我们的连通性检查（flood-fill）是"事后检查"，割生成是"事前推断"
- **体量**：~200 行
- **预期**：compass/watchtower 簇的连通性推断增强
- **风险**：中

**优先级**：P2

### 1.8 CRVR 分支启发式（Conflict-Recent Variable Reduction）

**核心思想**：近期矛盾涉及的变量（边）降低分支优先级。

**与本项目的关系**：
- edge_csp 的 `select_edge` 可以集成
- **体量**：~20 行
- **预期**：轻微改善分支选择
- **风险**：极低

**优先级**：P2

### 1.9 ML/神经方法 — **不推荐**

**关键发现**：[Böther et al. 2022] 复现研究显示 GNN 引导搜索"可以被随机值替代"，
增益来自 kernelization 而非神经网络。**神经方法对精确组合优化不可靠**。
AutoSAT（LLM 生成 CDCL 启发式）有趣但不实用。

**优先级**：不推荐

### 2.2 与参考求解器的差距（仅剩搜索层面）

| 层面 | 参考求解器 | 本项目 | 差距 |

### 2.3 结论

参考求解器的传播技术已全部吸收。剩余 ~28 FAIL 需要：
1. **搜索增强**（CBJ/LDS/重启）— 两者都缺，业界成熟技术
2. **LCG 学习** — 两者都缺，业界 Chuffed 验证的范式升级
3. **并行 Portfolio** — 两者都缺，利用多核
