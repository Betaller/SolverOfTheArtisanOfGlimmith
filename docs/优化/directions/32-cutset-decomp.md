# 32 · Cutset / 关节变量分解

> 状态：🟢 新方向 ｜ 分类：搜索 / 分解 ｜ 来源：本文新调研（24 未覆盖）
> 关联：[20-active-decomp.md](20-active-decomp.md) · [21-deduction-engine.md](21-deduction-engine.md) · [19-simd-flood.md](19-simd-flood.md)

## 1. 一句话
[20](20-active-decomp.md) 依赖「被边界切开的**物理**子网格」；本方向处理**没被物理切开、但存在小关节变量集**的情况：找出一小撮格/边（cutset），一旦枚举它们的取值，剩余问题就分裂成独立子问题 —— 即 CSP 的 cutset conditioning / 循环割集。

## 2. 思想（为什么有效）
- CPS 理论：约束图的**循环割集**（cycle cutset）—— 若约束图有环，搜索会指数爆炸；但若能找到一个小割集 C，枚举 C 的所有取值后，剩余图变成**树**（无环），树结构约束可在 O(n·d²) 内**定向求解**（无需回溯）。
- 本题的约束图：格为节点（区域归属变量），邻接 + 规则约束为边。虽然网格图本身环密集，但**约束**主要沿「区域边界」和「线索」分布 —— 割集可能远小于直觉（例如所有 clue 格 + 少数关键边）。
- 与 [20](20-active-decomp.md) 的区别：20 是「物理切分」（要求边界确定），本方向是**逻辑切分**（枚举少量变量即可让问题解耦），适用范围更广 —— 即使网格没被切开也能用。
- 收益形态：从 O(d^n) 降到 O(d^|C| · n)，只要 |C| 小就是数量级收益。

## 3. 现状与代码位置
- 无 cutset / 树分解相关代码。
- 约束图信息可从 `Puzzle` 直接构造（格 + 边 + 顶点约束，`types.rs:123`）。
- clue 格（number/symbol/compass/watchtower 等）天然是「高约束变量」，是割集的优质候选。
- 相关：[20](20-active-decomp.md) 的分解调度、`21` 的 deduction。

## 4. 收益
- 对「网格没被物理切开、但约束集中在少数格」的题（很多 area/compass/rose 题）是结构性加速。
- 与 [20](20-active-decomp.md) 互补：两者可级联（先物理切分，再对子问题做 cutset 分解）。

## 5. 代价与风险
- **风险：中**。割集若选不好（太大或不是真割集），收益消失甚至更慢；「树结构可定向求解」需要把规则改写成可沿树传播的形式（工程量大）。
- **代价**：中–大（~500–900 行：约束图构建 + 割集启发 + 枚举 + 树求解）。

## 6. 优先级 / ROI
- **P3**，ROI 中（理论收益大但工程量与不确定性都高；24 未列）。建议先做**只读分析**：统计官方题的约束图割集大小分布，确认可行性再投入。

## 7. 实现思路
```
// 阶段 0（可行性调研，低成本）：
//   对 2488 题建约束图，跑贪心割集启发，统计 |C| 分布
//   若多数题 |C| ≤ 8 且 d 小 → 值得做
// 阶段 1：
//   1. 建约束图 G（变量=格/边，边=规则约束）
//   2. 贪心找割集 C：反复移除"度最高"或"移除后使图最断裂"的变量，直到 G\C 无环
//   3. 枚举 C 的取值（d^|C|），对每个取值：
//        a. 用 [21] deduction 传播 C 的赋值
//        b. 剩余问题按树/森林结构定向求解（无回溯）
//   4. 首个完整解即停
```
- 割集启发：优先选 clue 格（约束多、域小）、其次选度数高的边。

## 8. 验证方法
- 阶段 0 的割集大小分布（决定是否继续）。
- 正确性：`--baseline` REGRESSION=0；cutset 解法与常规解法结果一致（官方解比对）。
