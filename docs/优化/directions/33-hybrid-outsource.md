# 33 · 子问题外包给专用引擎

> 状态：🟢 新方向 ｜ 分类：混合范式 ｜ 来源：本文新调研（24 未覆盖）
> 关联：[21-deduction-engine.md](21-deduction-engine.md) · [01-parallel-inter.md](01-parallel-inter.md) · [19-simd-flood.md](19-simd-flood.md)

## 1. 一句话
`07`/`11` 已证伪「**整体**替换为 SAT/ILP/CP」（连通性指数编码、形状是子图同构）。但**把某个自包含的子问题外包给专用引擎**是另一回事：如顶点度可行性、面积差分约束、形状精确覆盖 —— 这些子问题编码紧凑，交给 SAT/ILP/MaxSAT 微求解器反而更强。

## 2. 思想（为什么有效）
- 证伪的是「整体替换」，不是「局部外包」。关键区分：
  - **坏**：把整个谜题（含连通性、形状匹配）编码成 SAT → 子句爆炸。
  - **好**：把搜索中反复出现的**小子问题**（≤100 变量）编码 → 微秒级求解，且通用引擎自带**学习能力/割平面**，比手写判定强。
- 适合外包的子问题（编码紧凑、无连通性）：
  - **顶点度可行性**：ring/brick 的「顶点度 ∈{0,2}」+ 全局边奇偶 —— 纯布尔，`11` §2.3 指出 ring/brick SAT 编码仅 ~2000 子句、微秒级。
  - **面积差分约束系统**：`a_u - a_v ≤ c` 已是差分约束，可用 Bellman-Ford（已有），也可用 LP/ILP 拿**更紧**的界。
  - **形状精确覆盖**：已有 DLX（`pieces.rs`），是精确覆盖子问题的最优解。
  - **watchtower 度数分配**：顶点被 N 个区域触碰 —— 小的整数规划。
- 与 [21-deduction-engine.md](21-deduction-engine.md) 的关系：deduction engine 是「手写传播器集合」，本方向是「把某些传播器换成通用引擎调用」。

## 3. 现状与代码位置
- 已有雏形：`prototypes.rs:139` `sat_boundary_feasible`（自写的边界 SAT 判定，非外部引擎）；`prototypes.rs:13` Bellman-Ford。
- `dlx.rs`（精确覆盖，自写，非外部）。
- 无外部求解器依赖（Rust 侧零外部 solver）。
- `22` 的结论：「正确形态 = edge_csp 传播内核的全局代数补全，非独立模块」——本方向与之**不冲突**：外包是**传播内核内部**的实现手段。

## 4. 收益
- 拿到比手写更紧的界（尤其面积/度数的组合约束）→ 更强剪枝。
- 借通用引擎的学习/割平面能力，无需自己实现。
- 对档②（传播缺口 ~25 道）可能直接补齐。

## 5. 代价与风险
- **风险：中**。引入外部依赖（如 `minisat` Rust binding、或进程间调用）；调用开销（IPC/FFI）可能吃掉收益 —— 必须**批量/惰性调用**（只在传播到不动点后调一次，而非每节点）。
- **代价**：中–大（~400–800 行 + 依赖管理）。

## 6. 优先级 / ROI
- **P3**，ROI 中（收益真实但依赖引入成本高；且 `22` 已论证「代数补全」路线更优）。**建议先验证单个子问题（如顶点度可行性）的外包收益，再决定是否推广。**

## 7. 实现思路
```
// 只在 deduction 不动点后调用一次（惰性），避免每节点开销
fn propagate_via_oracle(state) -> Result<(), Contradiction> {
    // 1. 抽取子问题：顶点度约束 + 已知边状态
    let cnf = encode_vertex_degree(state);        // ~2000 子句
    // 2. 调用微求解器（FFI / 独立进程）
    match sat_solve(&cnf) {
        UNSAT => Err(Contradiction),               // 立即剪枝
        SAT(assign) => state.apply_forced(assign), // 拿回被强制的边
    }
}
```
- 优先**零依赖**路线：先用自写但更强的判定（如完整单元传播 + 冲突学习），确认收益后再考虑外部引擎。
- 批量：把多个独立子问题合并成一次调用。

## 8. 验证方法
- 微基准：子问题编码 + 求解耗时（必须 << 当前手写传播耗时）。
- `--baseline` REGRESSION=0；对比「手写传播」与「外包传播」的剪枝强度（剪枝数/节点数）。
