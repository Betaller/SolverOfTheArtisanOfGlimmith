# 37 · 规则组合派生约束引擎

> 状态：🟢 新方向 ｜ 分类：约束传播 / 语料挖掘 ｜ 来源：本文新调研（24 未覆盖）
> 关联：[21-deduction-engine.md](21-deduction-engine.md) · [13-官方语料二级结论](../13-官方语料二级结论.md) · [31-feasibility-memo.md](31-feasibility-memo.md)

## 1. 一句话
`13` 已从官方语料归纳出「15 条规则语义结论 + 14 条可用二级结论」。本方向把这件事**系统化、自动化**：枚举规则组合，从语料中挖掘「多规则叠加时成立的更强约束」（派生约束），并编译进传播器 —— 把语料的统计规律转成剪枝。

## 2. 思想（为什么有效）
- 单条规则的约束是松的，但**组合**会产生单条不具备的强约束。例：
  - `precise`（每区面积固定 N）+ `different`（形状互异）→ 区域数 K = 总格数/N，且形状数 ≥ K（强约束，可预检）。
  - `compass`（四向计数）+ `area`（面积数）→ 面积下界 = 1+N+S+W+E，`11` §3.3 已列出，可闭式化（`13` 有 compass 面积界推导）。
  - `rose_window` + `solitary` → 每区恰 1 clue 且含所有符号 → K = 符号数，且每个 clue 格必须是符号格（强定位）。
  - `block`（矩形）+ `ring`（无 3 路交叉）→ 矩形拼接的顶点结构受限（可推出大量边）。
- 这些是**语料级别的结构性规律**，不是靠搜索能发现的；一旦形式化，就是极强的预搜索剪枝（常数时间否掉大量错误分支，甚至直接判无解）。
- `13` 已手工做了 15+14 条；本方向是把它**自动化 + 补全**（枚举 22 规则的 2/3 组合，共 ~1500 对，用语料验证每对是否蕴含新约束）。

## 3. 现状与代码位置
- 已有手工结论：`docs/优化/13-官方语料二级结论.md`（15 条语义 + 14 条二级结论，附验证数据）。
- 传播器：`prototypes.rs`（BF/GF2/SAT）、`edge_csp/prop.rs`（10+ propagator）。
- 预检：`mod.rs:423` `pre_search_topology_check`（只查 ring/brick）。
- `shapes.rs:115` `area_bounds`（已含 compass 派生 min）—— 是派生约束的现存实例。

## 4. 收益
- 把「语料统计规律」变成「编译期可用的剪枝」——这是**纯增量**（语料已存在，结论已部分手工得出）。
- 预搜索即可否掉大量不可行分支/整题，对多规则组合题（失败主因，`21` §1.2）是广谱提升。
- 与 [21-deduction-engine.md](21-deduction-engine.md) 天然契合：派生约束就是新的 propagator。

## 5. 代价与风险
- **风险：中**。从语料归纳的规律**可能是假结论**（`13` 明确记录了「5 条解析陷阱」与「已证伪清单」）。每条派生约束必须：① 形式化证明；② 语料全量验证（无反例）；③ 单测固定。**误用假结论会剪掉正解。**
- **代价**：中（挖掘脚本 ~300 行 + 每条约束的证明/验证/传播器 ~100 行/条）。

## 6. 优先级 / ROI
- **P2**，ROI 中高（语料现成、结论部分已有；但每条都需严格证明，不能只靠统计）。建议**先形式化 `13` 已有的 14 条二级结论**（低风险、已验证），再自动化挖掘新的。

## 7. 实现思路
```
// 阶段 1（低风险，先做）：把 13 的 14 条二级结论逐条实现为 propagator / 预检
//   e.g. compass 面积下界闭式解 → shapes.rs:area_bounds 已部分实现，补全
//        precise+different → K = total/N，形状数 ≥ K 预检
//        rose+solitary → clue 格必须与符号格重合（定位约束）
// 阶段 2（自动化挖掘）：
//   1. 枚举规则组合（2 组合 ~231 对，3 组合 ~1540）
//   2. 对每组合，在语料上统计"是否总成立"的候选命题
//      候选命题生成器：面积整除性、K 的闭式、区域数上下界、边数奇偶…
//   3. 候选 → 形式化证明（人工/自动）→ 通过者进 propagator 库
//   4. 语料全量回归验证（无反例）＋ 单测固定
```
- 关键纪律：**统计相关 ≠ 逻辑必然**。只接纳可证明的；统计规律仅作启发（如 [05-ml-routing.md](05-ml-routing.md) 的路由）而非硬剪枝。

## 8. 验证方法
- 每条约束：语料全量无反例 + 单测 + [25-diff-fuzz.md](25-diff-fuzz.md) 差分（开/关该约束解集一致）。
- `--baseline` REGRESSION=0。
