## aog 自由形状搜索内存增长曲线（8x10m22-watch）

```
t=1s  VmRSS=   6.2 MB
t=2s  VmRSS= 620.6 MB
t=3s  VmRSS= 1236.1 MB
t=5s  VmRSS= 2652.5 MB
t=8s  VmRSS= 4765.7 MB
t=10s VmRSS= 6001.0 MB
```
- 增长速率约 **600 MB/s**，线性无收敛。
- AOG_DEBUG 计数：6 秒内 `shape_insert` 触发 ~6.8 万次，`next_shape_index` 到达 6.7 万+。
- 跑满 30s deadline 后 RSS 平台在 ~6.8 GB **不再回落**（形状库全程驻留），且 swap 抖动下
  deadline 检查无法按时执行，进程实际远超 30s。

## 结论

1. **P0 级内存问题：aog 自由形状搜索的形状库无界增长**（8×10/9×10 盘 → 5~7GB）。
   无尺寸约束题（官方 1649/2488）中无法快速解出的会内存爆炸。
2. **P0 级：rose region_match 候选 visited 无上限 + 多层克隆**（C4-2 → 102MB）。
3. **P1 级：aog `Pools::new(100)` 预分配 100 层 PlaceLevel**（每层 ~36KB → 常驻 ~3.6MB，
   小盘也如此，占 A1-1 5.6MB 的约 2/3）。
4. backtrack `HashMap` 状态 / `Cell` 192B / DLX 节点 48B 为次要热点。
